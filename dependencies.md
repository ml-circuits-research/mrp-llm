# Dependency record

MRP-LLM requires Node.js >=22.13 and its built-in modules, including `node:sqlite`. The root `package.json` declares one npm dependency, `pworker` (`file:../Ploinky-Worker`): Ploinky Workers, the model gateway every model call goes through (DS027); it is the owner's sibling project, used in place and never copied, with no dependencies of its own. The reasoning engines vendored under `reasoning/strategies/*/vendor/` and `eval/reference-engines/datalog-soplab/vendor/` are copied verbatim (each file with a `VENDORED:` header) from the archives `sop_reasoner_e10.zip`, `soplab-v0.4.0.zip`, `sop-r.zip` and `vrc03r.zip` kept in the ChatSOP repository (`experiments/`). ML training, optional external solvers, and CPU model serving have separate prerequisite checks. Neither an existing command nor a configured model proves a dependency is installed or licensed for redistribution. All exact upstream revisions, resolved transitive dependency lists, and license obligations for downloaded models and external packages must be recorded before distributing their artifacts. This file records declared requirements and unresolved facts; it does not authorize installation.

## Model gateway: Ploinky Workers

Every model call of the project goes through Ploinky Workers (`Ploinky-Worker/`, owner decision 2026-10-03): its server, library, CLI, job runner, skills and plugin sandbox use Node built-ins only and add no dependency; the root package still declares no npm dependency. The local models it serves are llama.cpp `llama-server` processes (binary and GGUF paths in `the Ploinky user configuration (~/.pworker/config.json)`), installed by the owner outside the repository; their weights are recorded below. Its home folder `~/.pworker/` (keys, request log, cache, audit store, runs) lies outside the repository.

## Dictionary data (bilingual dictionary of the edges)

Since the owner decision of 2026-10-01 (English-only core) the product linking path reads only the English synonym view of this data (`englishDictionary()`); the Romanian columns and the Wiktionary data serve language identification (LanguagesUtil), the gloss backend of TranslatorService and the archived evaluations.

`sop/dictionary.mjs` and its maintenance CLI `probably_obsolete/tinyLLMExperiments/tools/dictionary.mjs` are plain Node code with no package dependency: the sources are tab-separated text files in `config/dictionary/`, parsed and compiled by about two hundred lines of local code into lookup maps cached under `state/cache/dictionary/` (keyed by the SHA-256 of the sources). A dictionary or NLP package would add an opaque lexicon and inflection model; the host needs only exact lookups over reviewable data, so none is used.
