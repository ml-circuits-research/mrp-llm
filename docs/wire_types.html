Wire help

Wire help overview

The formalizer writes query circuits, conditional assumptions and optional turn-local session definitions; the runtime builds inspectable execution circuits. Definitions use the knowledge syntax of predicate, rule and default, are validated against memory and, once valid, are stored in the session layer. Session circuits and answer-shape self-check. Variables such as ?xx and ?yy describe unknowns whose matches stay together. Matching intuition and engine responsibilities.

Argument questions (Q-LANG-10): a query may name options with candidate $id (a supposed stated wire or a session rule, in force only for that question) and ask mode effect (what each option does to a claim) or mode abduce (which options explain it, and which are necessary); if $r may suppose a session rule. See query and Query modes.

Queries distinguish closed-list absence from explicit negative evidence. Two amounts with units are compared as written quantities (compare "1 hour" above "3000 seconds") and converted through the unit facts the memory marks with reading unit_amount and reading unit_dimension. Numeric assignments use one constraint scope with conjunctive requirements, preserving their original domains. A problem that states its own data (a word problem, a puzzle, a logic exercise) is modelled from its own text: session predicate declarations for its vocabulary, stated wires for its data (numbers are integers or decimals), session rules with exact compute arithmetic (rule) for its general statements and computations, then one query per question or one constraint for a puzzle (DS014 "Problems that state their own data").

Quoted time ranges retain explicit endpoint years and exclusive ends; during and overlaps ask different questions.

A random sample: order random with limit N on a mode select query draws N answers from the full answer set with the turn's seed ("a random fact", "give me some examples").
