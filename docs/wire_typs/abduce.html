All wire types

abduce

Abduction searches for minimal sets of possible causes that could explain an observed ground target under admitted rules. A proposed explanation remains hypothetical; no candidate is asserted. Trusted system/tool circuits can use this operation; model-authored declarative input cannot invoke it directly.

SOP syntax: @id type, exactly two leading spaces on each field line, $id for a computed value, ~id for a declaration handle, and ?x for a local logic variable or an output name. Atoms use [not ]predicate term1 [term2 [term3 [term4]]] with one to four whitespace-separated terms; lowercase predicate names, canonical symbols, JSON-quoted strings or safe integers. Parenthesized predicate(arg, …) and comma-separated arguments are not executable syntax.

Fields and inputs

KeywordCardinalityAccepted value, default and effect
queryAt most once; optionalA single $query value; it must be a query declaration. For abduce/diagnose its atoms must be ground. For simulate/temporal it determines selection, filters and time; no query handle (~query) is accepted.
dataAt most once; optionalOne $value or ~declaration, optionally a packed array. Admitted facts/rules participate in the finite proof; hypotheses are fallback candidates. Patterns are not rules. A numeric constraint here returns unsupported rather than being dropped.
memoryAt most once; optionalOne $link reference to a retrieval result, normally from link. A query declaration handle is not a retrieval; omitted memory triggers host-backed linking only when a repository/session and a retrieval query are available. Without either, local data is used.
observationAt most once; optionalOne $fact value or ~fact declaration. If query is omitted, this fact creates a ground query at runtime now; if query exists, observation does not replace it.
candidatesAt most once; optionalOne $hypothesis, ~hypothesis or packed $array. Every item must be a hypothesis; omission uses hypothesis objects in data, otherwise backward-generation of missing ground rule leaves.
reasoningAt most once; optionalA strategy name (plain token), default host policy.reasoningStrategy (reference by default). Built-ins: reference (the js-reference oracle; js-reference and js-oracle are the same route) and the deprecated advanced (the oracle plus optional external backends for deduction and numeric constraints). The host may restrict allowed strategies.
policyAt most once; optionalOne $policy value or ~policy declaration handle. It must lower to a policy object; each specified positive integer budget caps the corresponding host budget by min(host, wire). No policy reference means host limits alone.
outputRepeatable; optionalRepeatable ?name [one|many|rows|count|status] declaration, default one. Each output becomes a deferred $name value if bound; names must be unique and cannot collide with explicit wires. status binds result status even for incomplete results. Other modes require completeness; unusable/unselected modes become blocked, not arbitrary first answers.
afterRepeatable; optionalRepeatable $wire value-dependency reference. Orders execution after that producer; it does not alter inputs, proofs or output. A ~definition handle is graph-checked but is not a value-ordering dependency.

query or observation must be supplied at runtime; neither is marked parser-required. Query atoms must be ground, with no ?variable. A memory input, if supplied, must be a retrieval result. Automatic linking uses the query when a repository and session exist.

Result and limits

The result is the oracle's packet: status hypotheses (every inclusion-minimal explanation, cheapest first), unknown (reason no_explanation) or budget_exhausted (reason hypotheses when more than maxHypotheses candidates, candidates, nodes or wall); hypotheses (the atom texts of each explanation), explanations ({hypotheses: [ids], atoms: [texts], cost}), candidate_count, rejected ({id, reason}: repeats_the_observation, contradicts_an_observed_fact, status_rejected), generator when the candidates were generated, guarantee, budget, complete, used and notes. An explanation is a hypothesis, never a fact. The observed target is removed from the base evidence to avoid circular proof. Declared output one/many/rows projects the explanation records, count is unsupported, status projects status.

All operations use bounded search (host defaults include maxNodes 5000, maxDepth 8, maxCandidates 512, timeoutMs 3000); a ~policy can only tighten configured limits. The result records completeness and epistemic status relative to supplied finite inputs and the visible memory view, never calibrated truth probability. No operation here writes to the repository; after is only scheduling. Subsets are tried by increasing size and a superset of an explanation is skipped; rejected, directly circular or explicitly contradicted candidates are reported in rejected. Each subset tried counts against maxCandidates; a cut is budget_exhausted and never a shortened list.

Executable examples

Supply explicit candidate

@target query
  where outage server
  mode exists
@cause hypothesis
  holds network_down server
@ruleA rule
  when network_down ?x
  then outage ?x
@request abduce
  query $target
  data ~ruleA
  candidates ~cause

The rule is a trusted local definition (model-origin programs cannot author rules). The explanation is conditional on network_down server, not an assertion that the network is down.

Generate missing leaves

@wanted query
  where outage server
  mode exists
@approved rule
  when disk_full ?x
  then outage ?x
@why abduce
  query $wanted
  data ~approved
  output ?causes many

With no candidates, the finite backward generator can propose disk_full server as a ground missing condition. $causes is the projected explanation array if complete.

Invalid or unsafe use

@ungrounded query
  where outage ?device
  mode exists
@why abduce
  query $ungrounded

The parser accepts this program, but abduction rejects a target with ?device; supply a ground observation or ground query.
