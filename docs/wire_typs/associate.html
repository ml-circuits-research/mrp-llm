All wire types

associate

Association ranks explicitly supplied cases against a cue by lexical overlap, shared features or a bounded RecallMemory projection. Its scores are retrieval hints, not logical support or probabilities. Trusted system/tool circuits can use this operation; model-authored declarative input cannot invoke it directly.

SOP syntax: @id type, exactly two leading spaces on each field line, $id for a computed value, ~id for a declaration handle, and ?x for a local logic variable or an output name. Atoms use [not ]predicate term1 [term2 [term3 [term4]]] with one to four whitespace-separated terms; lowercase predicate names, canonical symbols, JSON-quoted strings or safe integers. Parenthesized predicate(arg, …) and comma-separated arguments are not executable syntax.

Fields and inputs

KeywordCardinalityAccepted value, default and effect
cueAt most once; requiredOne $query, $trace, ~trace or other typed $value. Query atoms or trace features form relational cues; only a trace text supplies lexical words. An unrecognized cue yields empty cue features, not an inference.
dataAt most once; requiredOne $trace, ~trace or packed $array containing only trace objects. Required even though the collection may be empty.
modeAt most once; optionalExact relational (default), lexical or recall-memory. Relational and lexical scores use Jaccard overlap; recall-memory scores occupied RecallMemory projection cells. Unknown mode throws during operation.
reasoningAt most once; optionalA strategy name (plain token), default host policy.reasoningStrategy (reference by default). Built-ins: reference (the js-reference oracle; js-reference and js-oracle are the same route) and the deprecated advanced (the oracle plus optional external backends for deduction and numeric constraints). The host may restrict allowed strategies.
policyAt most once; optionalOne $policy value or ~policy declaration handle. It must lower to a policy object; each specified positive integer budget caps the corresponding host budget by min(host, wire). No policy reference means host limits alone.
outputRepeatable; optionalRepeatable ?name [one|many|rows|count|status] declaration, default one. Each output becomes a deferred $name value if bound; names must be unique and cannot collide with explicit wires. status binds result status even for incomplete results. Other modes require completeness; unusable/unselected modes become blocked, not arbitrary first answers.
afterRepeatable; optionalRepeatable $wire value-dependency reference. Orders execution after that producer; it does not alter inputs, proofs or output. A ~definition handle is graph-checked but is not a value-ordering dependency.

Unlike logical memory retrieval, association does not silently query the repository; the data field provides all cases. cue is one object and data may flatten a pack. A policy limits candidates and search.

Result and limits

Returns status approximate (unknown when nothing ranks) with guarantee approximate, ranked candidates (trace IDs, scores, source and features), the meaning of the score, complete and budget. Output one/many/rows projects these candidate records; count unsupported; status projects approximate or unknown. Zero score is not a logical refutation.

All operations use bounded search (host defaults include maxNodes 5000, maxDepth 8, maxCandidates 512, timeoutMs 3000); a ~policy can only tighten configured limits. The result records completeness and epistemic status relative to supplied finite inputs and the visible memory view, never calibrated truth probability. No operation here writes to the repository; after is only scheduling. The recall-memory mode builds a transient feature bank from explicit cases; it does not enumerate unknown identifiers from memory. Candidate lists can truncate, in which case complete is false.

Executable examples

Shared features

@cue trace
  feature alarm motor1
@case1 trace
  feature alarm motor1
  feature stopped motor1
@case2 trace
  feature alarm motor2
@cases pack
  items $case1 $case2
@matches associate
  cue ~cue
  data $cases
  mode relational

The matching atom in case1 contributes to feature overlap; similarity is not proof that stopped motor1 follows from an alarm.

Lexical retrieval

@cue trace
  text "bearing vibration"
@bearing trace
  text "bearing vibration at pump"
@temperature trace
  text "high temperature at pump"
@cases pack
  items $bearing $temperature
@matches associate
  cue ~cue
  data $cases
  mode lexical
  output ?hits many

The lexical mode compares normalized word sets from trace text; $hits is the ranked candidate array when complete.

Invalid or unsafe use

@cue trace
  feature alert m1
@f fact
  holds alert m1
  valid timeless
@bad associate
  cue ~cue
  data $f

The parser accepts the fields, but association rejects the input with Association candidates must be traces: every data item must be a trace, and an admitted fact is not a case. (Writing data ~f fails earlier, because a fact definition handle is not readable as data; use $f.)
