binding

Internal result projection created by the runtime for an explicit output port. Authors declare output ?name one on solve or supported advanced operations; they cannot declare @name binding in executable source.

Status and author: Runtime-generated only; model-origin and trusted source both fail if they contain an explicit binding wire.

Accepted fields

Single means at most once, repeatable means zero or more, and required means at least once at parse time. Other field names are rejected.

FieldCardinalityAccepted values and current behavior
resultAt most once; required internallyRuntime-created result projection from a producing operation; never an author-supplied result packet.
variableAt most once; required internally?name of the declared output port; identifies the projected variable or status/count port.
modeAt most once; required internallyOne of one, many, rows, count, status; enforces output cardinality and shape.
ownerAt most once; required internallyProducing operation wire ID; ties this internal binding to its result.

Execution and result

The producer reserves ?name and runtime generates an internal @name binding; downstream code reads $name only when bound. one needs exactly one distinct answer; none yields no_answer and several yield ambiguous. many yields the array (including an empty array for a complete empty result), rows yields binding rows, count requires a count result, and status yields the producer status. Unsupported/inconsistent/both/mixed temporal or incomplete packets cannot silently become a chosen value (status mode is the explicit status exception). Conflicted relational candidates block ordinary projection. Numeric projections use result-specific outputProjection; a missing projection is unsupported. Runtime stores outcome, owner, proof IDs and epoch in outputs; the bound scalar/array becomes the wire value.

Current SOP examples

Unique value is consumable

@q query
  select ?parent
  where parent ?parent bogdan
  mode select

@answer solve
  query $q
  output ?parent one

@label value
  data "Parent: " + $parent

Requires a complete view with exactly one supported parent; then runtime creates the internal binding and label. With zero/multiple answers, the label is blocked.

Explicit status port survives unknown answers

@q query
  where parent ana bogdan
  mode exists

@answer solve
  query $q
  output ?state status

@label value
  data "Result: " + $state

The generated status binding carries the reasoner status as data, even when there is no selected individual.

Invalid or unsafe example

@q query
  where parent ana bogdan
  mode exists

@invented binding
  result $q
  variable ?x
  mode one
  owner q

The parser recognizes the fields and every reference exists, but Runtime.run rejects all explicitly declared binding wires, including trusted-origin programs, with binding wires are runtime-generated; declare solve output instead. A binding whose result names a missing wire fails even earlier, at graph validation (Unknown reference).
