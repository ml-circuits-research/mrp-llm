code

A program for a task: language, entry function, body and producer. It is opaque to every engine and runs only in the code-sandbox strategy, against the test wires of the same task.

Status and author: Host or turn wire: written by a model (llm-agent), the user, a renderer or a dream pass. Never knowledge approved from a source, never on the small-model surface, never evidence. A verified body may become a library component through a host write (version, approval and provenance are then host-written; an author never writes approval).

Accepted fields

Single means at most once, repeatable means zero or more, and required means at least once. Other field names are rejected (unknown_field). The table is generated from the grammar in sop/knowledge/grammar.mjs.

FieldCardinalityAccepted values and behavior
ofAt most once; requiredThe task symbol the program is for; the test wires with the same symbol are its tests.
languageAt most once; requiredjavascript (the only language of the sandbox in P0).
entryAt most once; requiredThe name of the function the tests call: a JavaScript identifier. The body must define it (code_entry_not_defined).
bodyAt most once; requiredThe whole program as ONE JSON string (\n for line breaks). Plain JavaScript: no require, import, network, filesystem, timers or async; the sandbox offers the ECMAScript built-ins only. export function f is accepted and stripped. The body is opaque to every engine.
produced_byAt most once; optionalrenderer|llm-agent|user|dream: who wrote the program.
versionAt most once; optionalA positive integer. A library component is versioned like a governed wire.
supersedesAt most once; optionalThe $code wire this one replaces (a new version, never an edit).
approvalAt most once; optionalproposed|approved|contested|rejected|superseded|retired. Written by the host when the owner accepts a verified program into the library; an author never writes it.
approved_byAt most once; optionalText; written by the host.
approved_atAt most once; optionalAn ISO date; written by the host.
retired_atAt most once; optionalAn ISO date after which the component no longer binds.
scopeAt most once; optionalText: where the component applies.
quoteAt most once; optionalQuoted source text, for a component taken from a reviewed source.

What it is for and how to write it

One code wire per candidate program, in candidate.sop for the host loop. The body is a JSON string; the entry names the function the tests call. The program must be synchronous, deterministic for the tests and free of side effects: it runs in a fresh context with no require, no process, no network and no filesystem.

What the engine does

Nothing in a reasoning route. The code-sandbox strategy loads the body in a vm context inside a worker thread (empty environment, heap limit, wall-clock guard), runs each test and reports verified, failed or budget_exhausted. The packet of the host loop carries the program with its producer and the verification it passed, route proposer when a model wrote it.

Examples

A candidate and a test; the sandbox answers verified.

@sum_list code
  of t1
  language javascript
  entry sumList
  body "export function sumList(xs) {\n  let s = 0;\n  for (const x of xs) s += x;\n  return s;\n}\n"
  produced_by llm-agent
  version 1
@e1 test
  of t1
  call "sumList([4, 5])"
  expect "9"
  kind example

Common mistakes

  1. Writing the body with real line breaks: it is one JSON string, so line breaks are \n and quotes are escaped.
  2. Using require, import, fetch or await: the sandbox has none of them, so the program fails with a ReferenceError or a SyntaxError.
  3. Writing approval, approved_by or approved_at: the host writes them when the owner accepts a component.
  4. Reading verified as correct for all inputs: it means these tests passed (guarantee bounded).
