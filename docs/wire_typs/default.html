default

A defeasible rule: a normal tendency with exceptions. "Usually", "normally", "as a rule ... except" are defaults; "always" and "never" are rules. The default concludes its head for every binding of its body unless an exception holds, a strict contrary is derivable, or a default that overrides it fires.

Status and author: Knowledge wire, written by a model or the owner from a source and stored by the host after review. A model-origin program cannot author it (the model-origin compiler rejects it). Governed: its `version`, `supersedes` and `approval` fields decide which version binds. It is sugar: the program that sop/knowledge/desugar.mjs generates (stratified negation as failure over `x_` predicates) is its normative meaning, so an engine needs only negation as failure to support it.

Accepted fields

Single means at most once, repeatable means zero or more, and required means at least once. Other field names are rejected (unknown_field). The table is generated from the grammar in sop/knowledge/grammar.mjs.

FieldCardinalityAccepted values and behavior
whenRepeatable; requiredThe body, a conjunction of atoms or one all/any group of condition leaves (not, absent, compare, compute, order, start_of, end_of). Head variables must occur in a positive atom (unsafe_head).
thenAt most once; requiredOne atom, possibly negative (then not pacifist ?x).
exceptRepeatable; optionalA condition group; the default does not apply to a binding where any except holds. Repeatable. Its variables must be bound by the body (unsafe_exception). An exception predicate needs retrieval completeness for the candidates, not a closed world.
priorityAt most once; optionalAn integer, default 0; sugar for overrides between defaults with contrary heads. Prefer overrides: global numbers do not compose across chapters written by different agents.
overridesRepeatable; optionalA $default that this default blocks, for the same arguments, whenever this one FIRES. The two heads must be contrary atoms of one predicate (overrides_not_contrary); the override graph must be acyclic (overrides_cycle).
sourceAt most once; optionalQuoted citation of the sentence the default comes from.
versionAt most once; optionalA positive integer. A revision is a new wire with version N+1 and supersedes $old; the old wire is never edited.
supersedesAt most once; optionalA $id of a wire of the same type with a lower version (supersedes_type_mismatch, version_not_increasing). An approved successor makes its predecessor approval superseded.
approvalAt most once; optionalproposed, approved, contested, rejected, superseded or retired. Written by the host when it accepts the wire; an author never writes it (authoring mode ignores it with governance_ignored). Only approved wires bind, and so do contested ones, flagged.
approved_byAt most once; optionalText. Written by the host at approval; required with approval approved in memory (approval_incomplete).
approved_atAt most once; optionalISO date or timestamp. Written by the host; asof selects the version in force from this date. Required for every norm and every strict method.
retired_atAt most once; optionalISO date or timestamp after which the wire no longer binds.
scopeAt most once; optionalA quoted list of tags (scope "ops, business_hours"). A scoped wire binds when its tags intersect the query context; an unscoped wire always binds.
quoteAt most once; optionalThe exact words of the source, copied byte for byte.

What it is for and how to write it

Write a default when the source states a tendency that has exceptions. Give each exception as an except group, and resolve a conflict between two defaults with overrides $other. A default needs a contrary or an exception: without one, write a rule. Do not declare the head predicate closed merely to make a default work; it is the exception and the strict contrary that must be looked up completely, not the head.

What the engine does

  1. Strict knowledge sits below every default. If the contrary of the head is derivable by an explicit negative fact (holds not flies tweety) or by a strict rule whose body does not depend on a default, the default is blocked and the answer is refuted, not both.
  2. overrides blocks by fire, not by applicability. A default that applies but is itself blocked by its own exception overrides nothing.
  3. Two defaults of equal strength with contrary heads both fire: the status is both (the Nixon diamond), never a silent pick.
  4. Before a default-derived row is accepted from a partial slice, the host looks up the strict contrary and each exception for each candidate; if the slice is incomplete the answer is widened or withheld.

The packet reports the author's wire (birds_fly) in used, never a generated x_ wire.

Examples

A default with an exception

@bird predicate
  args subject:entity
@penguin predicate
  args subject:entity
@flies predicate
  args subject:entity

@f1 fact
  holds bird tweety
@f2 fact
  holds bird pingu
@f3 fact
  holds penguin pingu

@birds_fly default
  when bird ?x
  then flies ?x
  except penguin ?x
  source "Field guide 1.1: birds normally fly, except penguins"
@q query
  where flies ?x
  select ?x

Tweety flies by default; pingu is a penguin, so the exception blocks the default and nothing is concluded about pingu.

The Nixon diamond and its resolution

@quaker predicate
  args subject:entity
@republican predicate
  args subject:entity
@pacifist predicate
  args subject:entity

@f1 fact
  holds quaker nixon
@f2 fact
  holds republican nixon

@d_quaker default
  when quaker ?x
  then pacifist ?x
@d_republican default
  when republican ?x
  then not pacifist ?x
@q query
  mode exists
  where pacifist nixon

Both defaults fire, so the status is both. Adding overrides $d_republican to the quaker default resolves the conflict in favour of pacifism:

@quaker predicate
  args subject:entity
@republican predicate
  args subject:entity
@pacifist predicate
  args subject:entity

@f1 fact
  holds quaker nixon
@f2 fact
  holds republican nixon

@d_quaker default
  when quaker ?x
  then pacifist ?x
  overrides $d_republican
@d_republican default
  when republican ?x
  then not pacifist ?x
@q query
  mode exists
  where pacifist nixon

Invalid: overrides between defaults that are not contrary

@a predicate
  args subject:entity
@b predicate
  args subject:entity
@d1 default
  when a ?x
  then b ?x
  overrides $d2
@d2 default
  when a ?x
  then b ?x

The validator reports overrides_not_contrary: overriding makes sense only between a conclusion and its contrary.

Common mistakes

  1. A default written for an exceptionless law, or a rule written for "usually" (a conflict then becomes both).
  2. Global priority numbers instead of overrides.
  3. Declaring the head closed to silence a retrieval question: the exception and strict-contrary predicates need keyed lookups, not a closed head.
  4. An exception whose variable the body does not bind (unsafe_exception).
  5. Recursion through an exception (not_stratifiable): the validator checks the desugared program.
