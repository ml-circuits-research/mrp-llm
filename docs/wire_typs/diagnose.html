All wire types

diagnose

Diagnosis first proposes abductive explanations, then compares explicit candidate tests by how many explanations they separate. It recommends tests but never performs them or asserts a cause. Trusted system/tool circuits can use this operation; model-authored declarative input cannot invoke it directly.

SOP syntax: @id type, exactly two leading spaces on each field line, $id for a computed value, ~id for a declaration handle, and ?x for a local logic variable or an output name. Atoms use [not ]predicate term1 [term2 [term3 [term4]]] with one to four whitespace-separated terms; lowercase predicate names, canonical symbols, JSON-quoted strings or safe integers. Parenthesized predicate(arg, …) and comma-separated arguments are not executable syntax.

Fields and inputs

KeywordCardinalityAccepted value, default and effect
queryAt most once; optionalA single $query value; it must be a query declaration. For abduce/diagnose its atoms must be ground. For simulate/temporal it determines selection, filters and time; no query handle (~query) is accepted.
dataAt most once; optionalOne $value or ~declaration; facts and rules supply the model, hypotheses can supply fallback candidates, patterns do not act as rules. A numeric constraint is rejected as unsupported.
memoryAt most once; optionalOne $link reference to a retrieval result, normally from link. A query declaration handle is not a retrieval; omitted memory triggers host-backed linking only when a repository/session and a retrieval query are available. Without either, local data is used.
observationAt most once; optionalOne $fact or ~fact. When query is absent, generates the observed target query at runtime now; query takes precedence if supplied.
candidatesAt most once; optionalOne $hypothesis, ~hypothesis or packed array. Omission uses hypotheses in data or finite generated missing conditions.
testsAt most once; optionalOne $query value or packed $array of queries. Every test must be a ground, single-atom query. Optional; with no tests, no next test is recommended. ~query is not a valid declaration handle.
reasoningAt most once; optionalA strategy name (plain token), default host policy.reasoningStrategy (reference by default). Built-ins: reference (the js-reference oracle; js-reference and js-oracle are the same route) and the deprecated advanced (the oracle plus optional external backends for deduction and numeric constraints). The host may restrict allowed strategies.
policyAt most once; optionalOne $policy value or ~policy declaration handle. It must lower to a policy object; each specified positive integer budget caps the corresponding host budget by min(host, wire). No policy reference means host limits alone.
outputRepeatable; optionalRepeatable ?name [one|many|rows|count|status] declaration, default one. Each output becomes a deferred $name value if bound; names must be unique and cannot collide with explicit wires. status binds result status even for incomplete results. Other modes require completeness; unusable/unselected modes become blocked, not arbitrary first answers.
afterRepeatable; optionalRepeatable $wire value-dependency reference. Orders execution after that producer; it does not alter inputs, proofs or output. A ~definition handle is graph-checked but is not a value-ordering dependency.

At runtime either query or observation must produce a ground target. The query controls automatic memory linking if repository/session exist. A supplied memory must be a $link retrieval result. Tests are evaluated under each candidate explanation, not fetched or executed in the world.

Result and limits

The result is the packet of abduce plus tests ({query, separated_pairs, predictions: [{explanation, status}]}, most separating first), next_test if a test separates at least one pair, executed_tests: false and the completeness flag. The score counts separated explanation pairs, not expected information gain. Output one/many/rows projects explanations (not tests); count unsupported; status returns status.

All operations use bounded search (host defaults include maxNodes 5000, maxDepth 8, maxCandidates 512, timeoutMs 3000); a ~policy can only tighten configured limits. The result records completeness and epistemic status relative to supplied finite inputs and the visible memory view, never calibrated truth probability. No operation here writes to the repository; after is only scheduling. Test predictions require bounded Horn closure and ground single-atom test queries. Missing predictions are unknown, not negative test results.

Executable examples

Compare two possible causes

@target query
  where outage server
  mode exists
@network hypothesis
  holds network_down server
@disk hypothesis
  holds disk_full server
@causes pack
  items $network $disk
@nrule rule
  when network_down ?x
  then outage ?x
@drule rule
  when disk_full ?x
  then outage ?x
@rules pack
  items $nrule $drule
@check query
  where network_down server
  mode exists
@diagnosis diagnose
  query $target
  data $rules
  candidates $causes
  tests $check

Both approved rules make the two assumptions potential explanations. The network test can separate their predictions; it is recommended only and is not performed.

Single-cause diagnosis

@q query
  where alarm device1
  mode exists
@r rule
  when temperature_high ?x
  then alarm ?x
@h hypothesis
  holds temperature_high device1
@test query
  where temperature_high device1
  mode exists
@result diagnose
  query $q
  data ~r
  candidates ~h
  tests $test

This produces an explanation candidate; with only one explanation there may be no discriminating next_test.

Invalid or unsafe use

@q query
  where alarm device1
  mode exists
@badtest query
  where temperature_high ?x
  mode exists
@result diagnose
  query $q
  tests $badtest

The parser accepts it, but diagnosis rejects a diagnostic test containing an unground ?x.
