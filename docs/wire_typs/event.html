event

An event describes a revision of an existing claim in a repository. The declaration produces a value, while an authorized remember applies it to the current session. It preserves a separate history of what was known and when: an end date changes valid time; a retraction changes which claims are visible to queries at a given asof. This is an advanced/review-sensitive authoring surface, not a way for a formalizer to rewrite a user claim without identifying it.

All supported fields

Field / multiplicityValue grammar and operational constraint
action — exactly one, requiredOne of end, retract, correct; unsupported names fail parser shape validation. end limits the target claim's exclusive validity endpoint; retract hides that claim in the later knowledge view; correct is expanded by remember into a retraction plus a new replacement fact.
target — exactly one, requiredLiteral claim ID such as c_... or $receipt from an remember receipt with ids containing exactly one claim. At runtime a $id value that is itself a one-element array of claim IDs is also accepted; neither shape bypasses the visible-claim check. Text not starting with $ is unquoted and passed to repository ID validation. A $receipt is a real dependency; a multi-claim receipt, event ID or arbitrary scalar is not a valid claim target. The claim must be visible in the current session/repository before its event is applied. If target comes from a newly written receipt, this dependency orders the operation.
effective — zero or one; required to apply endLiteral ISO YYYY-MM-DD or UTC timestamp YYYY-MM-DDTHH:mm:ssZ (optional milliseconds), converted with instant(). end additionally requires a finite instant when the event is applied, so open and beginning are not usable as its effective cutoff. The parser does not enforce the action-specific requirement. For retract/correct the parsed effective value is not stored in the resulting retraction event; an effective date does not make retraction a dated end. This field is not a $value instant dereference.
replacement — zero or one; required to apply correct$fact of a replacement fact, including atom, validity and provenance; correction fails at remember if missing or of another kind. The old claim is retracted and the replacement fact is separately written. On end/retract, a supplied replacement is materialized but not consumed as a new claim; do not put it there expecting a write.
source — zero or one, default userLiteral or JSON double-quoted source string, decoded with unquote. It identifies provenance of the revision event, not of a replacement fact (which has its own source). It is not a $ dependency nor a host-approved identity certificate. An omitted source silently records user, a trust class nobody wrote; write it explicitly.

Temporal history

Applied events get their own event IDs and knownAt write time. Claim visibility at query.asof considers only events known by that cutoff. For a visible end, claim validity ends at the minimum of its original end and the event's effective; the interval remains half-open. retract removes its target from later knowledge views without proving the atom's explicit negation. correct returns two receipt IDs and requires the replacement fact's retention pinned to pass host allowPin. The repository validates target claim existence and applies the batch transactionally.

Current syntax examples

Given a writable session, the first receipt identifies exactly one claim, so target $saved is an accepted target. An asof before the end write sees the earlier view even when at asks about a later validity date.

@original fact
  holds open gate_a
  valid 2026-01-01 open
  source "facility log"

@saved remember
  input $original

@stop event
  action end
  target $saved
  effective 2026-06-01
  source "closure notice"

@apply_stop remember
  input $stop

Correction retracts one claim and writes a distinct replacement fact; no assertion that open gate_a is explicitly false follows just from the retraction:

@old fact
  holds located package_a room_a
  valid timeless
  source "initial scan"

@receipt remember
  input $old

@new fact
  holds located package_a room_b
  valid timeless
  source "verified rescan"

@fix event
  action correct
  target $receipt
  replacement $new
  source "audit correction"

@apply_fix remember
  input $fix

The next fragment parses, but the receipt identifies two claims; event materialization rejects an ambiguous receipt rather than selecting the first ID:

@a fact
  holds open gate_a
  valid timeless

@b fact
  holds open gate_b
  valid timeless

@both pack
  items $a $b

@receipt remember
  input $both

@bad event
  action retract
  target $receipt
