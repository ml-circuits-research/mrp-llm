expand

Instantiates a named host-approved template or procedure with specific argument values and exposes its declared yield as this wire’s value.

Status and author: Only trusted host/tool circuits may author this operation. Small-model declarative input cannot emit it; host-approved orchestration supplies the required execution steps.

Accepted fields

Single means at most once, repeatable means zero or more, and required means at least once at parse time. Other field names are rejected.

FieldCardinalityAccepted values and current behavior
usingAt most once; requiredApproved ~template or ~procedure handle; selects the definition to expand, not a $value.
withRepeatable; optional; exactly one per declared parameter at expansionname value; one per declared parameter. $id reads a value, otherwise text is decoded if JSON-quoted; binds an expansion parameter.
afterRepeatable; optional; default none$wire dependency per line; orders expansion after an earlier value/effect without adding an argument.

Execution and result

Each with name value binds one declared parameter, once. A value beginning with $ resolves an existing wire value; other text is unquoted (a JSON-quoted string is decoded). Missing or duplicate parameters, unknown names, a bad body, ID collisions, or a yield outside body/output are errors. At expansion, the runtime creates namespaced parameter value wires and body wires, substitutes references, renames body output ports, then aliases the expansion result to its yield. Definition metadata does not turn this into arbitrary code execution.

Definitions loaded from the repository are matched by ID and verified checksum. A trusted invocation can contain an expand call; the host must supply the approved definition. If the yielded port is unbound, dependent wires remain blocked. Expansion is subject to maxWires/maxEpochs and graph-cycle checks. It never changes the rules for writing facts: any body remember still requires repository/session and host permission.

Current SOP examples

Approved template defined in trusted source

@calc template
  description "Add a reviewed offset to an input"
  cue "adjust score"
  params base offset
  yield total
  body |
    @total value
      data $base + $offset

@input value
  data 7

@offset value
  data 3

@use expand
  using ~calc
  with base $input
  with offset $offset

The with lines supply both arguments; @use receives the body’s 10 result.

Invoking a procedure with constant arguments

@check_rule procedure
  params measured threshold
  yield verdict
  body |
    @verdict value
      data $measured >= $threshold

@result expand
  using ~check_rule
  with measured 9
  with threshold 8

A trusted declaration is included for a self-contained example; expansion yields true. In a trusted invocation omit that declaration and rely on the exact approved library entry.

Invalid or unsafe example

@check_rule procedure
  params measured
  yield verdict
  body |
    @verdict value
      data $measured > 0

@bad expand
  using $check_rule
  with measured 9

The parser can recognize the reference, but runtime requires a definition handle ~check_rule; a value reference is not an approved template handle.
