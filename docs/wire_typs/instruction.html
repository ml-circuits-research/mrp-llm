instruction

An instruction wire is what the user asks about how the assistant should answer from now on: start or end every answer with some words, keep answers short or detailed, answer in a formal or a playful tone (the register of the conversation), stop an instruction, or say which instructions are active. The formalizer writes it in the same understanding step as the query (LocalLLMStepByStep through its instruction kind); it is never a fact and never evidence.

The runtime applies it to the caller-owned behaviour of the conversation (lib/conversation/behaviour.mjs, DS023 "Behaviour layer"): a prefix or suffix becomes a reply wire of its own situation whose text is the user's words, with a rule that makes it applicable on every turn (origin user); a style becomes a rule deriving the style. The JS oracle reads these wires with the conversation layer, so the instruction is followed because the reasoner derives it; do cancel withdraws the wires; do list answers with the active instructions. The packet reports instructions and behaviour (the active instructions and the changes of the turn).

Every accepted keyword

KeywordCardinality / defaultAccepted value and concrete effect
doExactly once; requiredset (add an instruction; one active per kind; short and detailed exclude each other, and so do formal and playful), cancel (withdraw the active instruction of the kind, or all of them without a kind) or list (say which are active; no kind and no text: instruction_list_form).
kindAt most once; required with do setprefix or suffix (start or end every answer with the text), short (the first line of every answer), detailed (never the short style), formal or playful (the register: the conversation layer derives cv_register, and the formal or playful variants of the register collections answer while it is active); instruction_kind_required when do set has none.
textAt most once; with prefix and suffix onlyThe words to add, one nonempty JSON-quoted verbatim part of the message (quotation marks of any style compare equal); instruction_text when a kind that needs it has none or another kind has one, instruction_text_not_in_message at admission when the words are not in the message.
spanAt most once; optionalThe verbatim part of the message that gives the instruction (instruction_span_not_in_message otherwise).
sourceAt most once; optionalThe id of the strategy that wrote the wire (local_llm_step_by_step); descriptive only.

A register for the conversation

EN “From now on please answer in a formal tone.”

@i1 instruction
  do set
  kind formal

No text: the kind is the register. Every later reply of the conversation uses the formal variant of its situation when the reply memory has one (smalltalk-professional-v1); playful withdraws it, and do cancel with kind formal ends it.

Start every answer with some words

EN “From now on always start your answers with «I'm here:»”

@i instruction
  do set
  kind prefix
  text "I'm here:"

The next answers begin with "I'm here:" until the user withdraws it.

Stop it, and list what is active

EN “Stop starting with I'm here. What are my instructions now?”

@i1 instruction
  do cancel
  kind prefix

@i2 instruction
  do list

Invalid: a set without a kind

@i instruction
  do set
  text "OK:"
