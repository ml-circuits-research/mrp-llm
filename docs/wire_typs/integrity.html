integrity

A pattern that must never hold in a state: "a room has one booking per slot", "a person has one home". Each match is reported as data with its witness; nothing breaks and the rest of the knowledge stays usable.

Status and author: Knowledge wire, written by a model or the owner from a source and stored by the host after review. A model-origin program cannot author it (the model-origin compiler rejects it). Governed: its `version`, `supersedes` and `approval` fields decide which version binds. It is sugar for one rule that derives `violation ID WITNESS`. Constraints on what may be done (actions, deadlines, trajectories) are norm wires, not integrity wires.

Accepted fields

Single means at most once, repeatable means zero or more, and required means at least once. Other field names are rejected (unknown_field). The table is generated from the grammar in sop/knowledge/grammar.mjs.

FieldCardinalityAccepted values and behavior
neverRepeatable; requiredThe forbidden pattern, a condition group (an atom or an all/any block with compare, not, absent, ...).
witnessAt most once; requiredThe ?variables that identify the violation; they must be bound by never.
messageAt most once; optionalJSON-quoted reason shown with the violation.
severityAt most once; optionalerror or warning.
sourceAt most once; optionalQuoted citation of the sentence the constraint comes from.
versionAt most once; optionalA positive integer. A revision is a new wire with version N+1 and supersedes $old; the old wire is never edited.
supersedesAt most once; optionalA $id of a wire of the same type with a lower version (supersedes_type_mismatch, version_not_increasing). An approved successor makes its predecessor approval superseded.
approvalAt most once; optionalproposed, approved, contested, rejected, superseded or retired. Written by the host when it accepts the wire; an author never writes it (authoring mode ignores it with governance_ignored). Only approved wires bind, and so do contested ones, flagged.
approved_byAt most once; optionalText. Written by the host at approval; required with approval approved in memory (approval_incomplete).
approved_atAt most once; optionalISO date or timestamp. Written by the host; asof selects the version in force from this date. Required for every norm and every strict method.
retired_atAt most once; optionalISO date or timestamp after which the wire no longer binds.
scopeAt most once; optionalA quoted list of tags (scope "ops, business_hours"). A scoped wire binds when its tags intersect the query context; an unscoped wire always binds.
quoteAt most once; optionalThe exact words of the source, copied byte for byte.

What it is for and how to write it

Write the pattern the source forbids as the body of never, name the thing a reader needs to find the culprit in witness, and say why in message. Declare the relation violation (two arguments, subject and object) in the knowledge so that a question can select the violations: the first argument is the integrity wire's id, the second the witness.

What the engine does

Each match of never derives violation ID WITNESS. A violation is an ordinary fact, so a question such as "which bookings violate the rules" is a normal query. It is deliberately never a hard assertion in any engine (a hard assertion would make a theory that contains the violation inconsistent, and from an inconsistent theory everything follows). Integrity over a whole memory cannot be checked on one retrieved slice (the second booking may be missing): the host checks it when a claim is ingested, through an index from predicate to integrity wires, or offline.

Examples

@booked predicate
  args subject:entity object:entity location:entity
@violation predicate
  args subject:entity object:entity

@b1 fact
  holds booked room1 slot9 ann
@b2 fact
  holds booked room1 slot9 bob
@b3 fact
  holds booked room2 slot9 cy

@no_double_booking integrity
  never all
    booked ?r ?s ?a
    booked ?r ?s ?b
    compare ?a not_equal ?b
  end
  witness ?r
  message "a room has two bookings in one slot"
  severity error
@q query
  where violation ?c ?w
  select ?c ?w

Room1 has two bookings in slot9, so the violation no_double_booking room1 is reported; room2 is unaffected.

Invalid: a variable under compare that nothing binds

@booked predicate
  args subject:entity object:entity location:entity
@bad integrity
  never all
    booked ?r ?s ?a
    compare ?a not_equal ?c
  end
  witness ?r

Common mistakes

  1. Using an integrity wire for something that may be done or not done (an action, a deadline): that is a norm.
  2. Forgetting that two bookings with the same value count as one match: compare the bound variables with compare ?a not_equal ?b.
  3. A witness variable that never does not bind.
  4. Expecting the engine to stop on a violation: it reports and continues.
