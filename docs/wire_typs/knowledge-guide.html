Knowledge wires: the manual

How to write, read and check the knowledge language: the wires a model or the owner writes from a source (a manual, a regulation, an article) and that the host stores as knowledge. SOP Lang has no version numbers: every change is documented here, in DS004 and on the wire pages in the same step. The grammar tables are generated from sop/knowledge/grammar.mjs.

They meet only through the roles of predicate and the host linking of DS014. The model-origin compiler rejects every knowledge wire. Several names exist on both surfaces with different fields; each such page has a section "Knowledge language" for the knowledge form.

The format

@name type            # header at column one: a letter, then letters, digits, underscore
  keyword value...    # exactly two leading spaces; one keyword per line
  when all            # a group opens with all or any and closes with end
    p ?x
    q ?x
  end
  • Terms: a lowercase symbol (paris), a safe integer (money in cents, time in minutes, no floats), a JSON-quoted string, a ?variable, a $ref to a wire, a ~action handle. Entities are lowercase symbols (alpha_lab); a string is only a text value or the content of source, quote, speaker, description, message.
  • Atoms: [not |absent ]predicate term..., zero to six terms, no parentheses, no commas, no symbol operators (above, at_least, plus, times).
  • Namespace: wire ids and predicate names share one; x_ is reserved for generated wires.
  • Dates: 2026-01-15 or a timestamp; beginning and open are the open ends.
  • Reification: an event with more than six participants is one event fact plus one fact per participant.

How to write knowledge

  1. Declare each relation with predicate: roles and types, closed only with the source sentence that says the list is complete.
  2. Write facts with their source, rules for laws, defaults for tendencies, aggregates for totals, norms and methods for procedures.
  3. Run node eval/smoke-reasoning/validator.mjs --authoring knowledge.sop query.sop and fix every error and warning; write at least one test query per rule and per procedure, including one that must be blocked or refuted.
  4. Never write approval, approved_by, approved_at, jsEval or an amendment.

The task procedure for an agent that compiles long texts is the skill skills/sop-wire-authoring/SKILL.md.

Every wire

One page per wire: predicate, fact, rule, default, integrity, aggregate, constraint, action, goal, method, norm, procedure, amendment, argument, trace, hypothesis, policy, query. The semantics shared by all of them are on Knowledge semantics, governance and modes of work on Governance and modes of work, the question forms on Query modes, and the trusted escape hatch on jsEval.
