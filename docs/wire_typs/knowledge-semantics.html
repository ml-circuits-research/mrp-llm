Knowledge semantics

What the engines do with the knowledge wires, the same for every strategy: two negations and closed, the paraconsistent both, defaults by fire and overrides, aggregates and open domains, snapshot time, conditional and used. Every example on this page is executed by the tests.

Finite, function-free, set semantics

Terms are constants, rules construct no new terms, duplicate derivations collapse, and compute is forbidden inside a recursive cycle, so evaluation terminates. A count counts distinct bindings of all variables of the counted group.

Two evidence derivations, four statuses

For a ground atom p a an engine derives positive evidence (p a is derivable) and negative evidence (not p a is derivable) independently (Belnap's four-valued logic). The status is supported (positive only), refuted (negative only), both (positive and negative) or unknown (neither). both is a reported status, not a state that stops propagation: a body p a is satisfied by positive evidence whatever the negative evidence is, a body not p a by negative evidence whatever the positive is. Evidence is therefore monotone (adding a fact never retracts a derived atom, which makes answering from a partial slice safe) and a contradiction stays local: nothing unrelated becomes derivable.

@bird predicate
  args subject:entity
@flies predicate
  args subject:entity

@f1 fact
  holds bird tweety
@f2 fact
  holds not flies tweety
@r1 rule
  when bird ?x
  then flies ?x
@q query
  mode exists
  where flies tweety

The rule derives positive evidence and the fact gives negative evidence: the status is both, reported, and nothing breaks.

Two negations and `closed`

not p a is explicit evidence that p a is false: the source says so. absent p a means "no record of it" and is allowed only for a predicate declared closed true; it is true when positive evidence is not derivable. Absence of evidence is unknown, never false. Closedness is a host review step: an author proposes it with the source sentence that asserts exhaustiveness, and the host accepts it only over an archived or pinned view so that forgetting can never turn a fact into a false absent.

@node predicate
  args subject:entity
@blocked predicate
  args subject:entity
  closed true
@open_node predicate
  args subject:entity

@n1 fact
  holds node a
@n2 fact
  holds node b
@b1 fact
  holds blocked b

@r_open rule
  when node ?x
  when absent blocked ?x
  then open_node ?x
@q query
  where open_node ?x
  select ?x

Wrong: when not blocked ?x where the source only lists blocked nodes (it never fires). Right: closed true and absent. A select or exists on a closed, non-derivable atom over a complete view is refuted; over an open one it is unknown.

Invalid: absent over an open predicate

@node predicate
  args subject:entity
@blocked predicate
  args subject:entity
@open_node predicate
  args subject:entity
@r rule
  when node ?x
  when absent blocked ?x
  then open_node ?x

Stratification

Negation as failure, exceptions and aggregates may not occur in a cycle of the predicate dependency graph (not_stratifiable). The check is conservative: it reads relation names and ignores polarity. Recursive aggregation is excluded; shortest-path and path-counting questions on cyclic graphs are planning or closure questions. The validator checks the desugared program, not the sugar.

Defaults, by fire

A strict contrary sits below every default (refuted, not both); overrides blocks by fire, not by applicability; two defaults of equal strength with contrary heads give both. See default.

Aggregates, counts, `every` and open domains

Over a predicate not declared closed, a count or aggregate is a lower bound (bound at_least), an every with no counterexample is unknown (reason open_domain), and a counterexample still refutes. The validator warns aggregate_needs_closed, count_needs_closed and every_needs_closed_scope. See aggregate and query.

Snapshot time

A stored fact holds at an instant when its interval contains it (valid START END, start inclusive, end exclusive); a derived atom holds at an instant when some rule instance has its whole body holding at that same instant, so its validity is the intersection of its body facts' intervals. at T is one instant, during S E means throughout, overlaps S E means at some instant, asof D means as known at D. start_of ?t ATOM and end_of ?t ATOM bind the start or end of a stored fact's validity (base predicates only, time_leaf_on_derived otherwise) and order ?t1 before ?t2 compares them. Under during, select returns the rows present in every part of the partition at the facts' endpoints and count the number of such rows; under overlaps only select is specified.

Epistemic status and `conditional`

A fact is observed, reported (with a speaker), hedged or supposed; everything but observed, and every proposed or rejected wire a query supposes, is an assumption. The host computes conditional per row: the assumption ids the row rests on, verified by a second run on the observed facts plus exactly that set. If the verification fails the row is conditional on all assumptions with conditional_unknown; under negation as failure the verification proves sufficiency only and the packet sets nonmonotone. A conditional answer is never promoted to evidence or stored.

`used` and proofs

used is one sufficient support set: the ids and versions of the facts, rules, defaults, actions, methods and norms that together re-derive the answer. It is not "the claims whose deletion changes the answer" (two facts that are each sufficient would give an empty set). Where a strategy does not provide it, the host runs the deletion method and verifies it by replay on that set alone; if the replay fails the packet says used_incomplete and promotes nothing. The packet reports the wire the author wrote, never a generated x_ wire.

Planning state

A planner state is polarity-explicit unless the fluent predicate is closed: with no evidence a precondition is unsatisfied (unknown is not true); with a closed fluent requires not p means p is absent.

Budgets

A strategy may stop early and never answers as if it had finished: an incomplete negative (unknown, refuted by failure, no_plan, an optimum) is budget_exhausted with a reason. See DS006 "Strategies".
