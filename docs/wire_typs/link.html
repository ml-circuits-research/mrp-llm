link

Connects an already declared query to local facts/rules and, when configured, visible memory claims and approved stored rules. It returns a retrieval plan and candidates, not a verdict.

Status and author: Only trusted host/tool circuits may author this operation. Small-model declarative input cannot emit it; host-approved orchestration supplies the required execution steps.

Accepted fields

Single means at most once, repeatable means zero or more, and required means at least once at parse time. Other field names are rejected.

FieldCardinalityAccepted values and current behavior
queryExactly once; required$query; chooses query goals for relevant repository/local retrieval.
dataAt most once; optional; default none$value or packed facts/rules; adds local evidence and approved rules to the link result.
strategyAt most once; optional; default host strategyRegistered retrieval strategy name, default host retrievalStrategy (hybrid by default); controls retrieval, subject to host allowlist.
afterRepeatable; optional; default none$wire per line; enforces dependency ordering, without adding evidence.

Execution and result

Local facts are tagged local/observed for this query, filtered by valid time and assigned local IDs; they are not stored in the session. The linker walks eligible rule conclusions into subgoals, includes their negated counterparts for conflict checks, retrieves candidate facts when repository/session exist, and records linkPlan, rules, facts, coverage, probes and complete. Without a repository/session, local data still works. Rules supplied as values must be approved host declarations in a trusted tool circuit. A hypothesis or pattern is not silently promoted to deductive evidence.

Retrieval strategy selects the memory engine path, not the reasoning backend. Pass $linked as reason.memory; solve.query generates this link stage automatically.

Current SOP examples

Local evidence without session

@evidence fact
  holds parent ana bogdan
  valid timeless

@question query
  where parent ana bogdan
  mode exists

@linked link
  query $question
  data $evidence

@answer reason
  query $question
  memory $linked

The reasoner receives the local fact through the retrieval packet; no repository write occurs.

Pack several local facts

@first fact
  holds parent ana bogdan
  valid timeless

@second fact
  holds parent bogdan carla
  valid timeless

@bundle pack
  items $first $second

@ask query
  where parent ana ?child
  select ?child
  mode select

@related link
  query $ask
  data $bundle

The pack is flattened into two local fact inputs. link retrieves candidates; it does not choose a child itself.

Invalid or unsafe example

@candidate hypothesis
  holds parent ana bogdan

@q query
  where parent ana bogdan
  mode exists

@bad link
  query $q
  data $candidate

Hypotheses are candidate assumptions, not fact/rule data. The text parses but the link runtime rejects this input kind.
