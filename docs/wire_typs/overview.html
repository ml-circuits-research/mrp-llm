Wire help

A SOP circuit describes claims, questions, and operations using named, typed wires. Formalizer means the role that translates supplied natural language into SOP, not a specific model. The intended small conversational model performs that bounded translation; a model can also formalize document content and can separately author richer definitions or programs for review. The host supplies approved knowledge, validates proposals, and controls permissions. The reasoning engine executes the declared problem; formalization itself does not solve it or establish its truth.

Intuition: unknowns, matches, and structured results

Read ?xx and ?yy as unknowns to be matched or solved together, not as instructions to create separate wires. One matching assignment can be represented by a structure such as {xx: 1, yy: 4}; multiple assignments can be represented by an array such as [{xx: 1, yy: 4}, {xx: 2, yy: 3}]. Each structure preserves the relationship between its members. Taking xx from one row and yy from another does not necessarily produce a valid assignment. Repeating the same variable within a condition means the same value must satisfy its occurrences; a different name introduces a different unknown.

This is an intuition for matching and solving, not a universal return type for every wire containing a question mark. The wire-type contract and the selected reasoning engine determine the supported result representation, while an explicit output mode determines what becomes a consumable wire value. Engines must document their semantics, supported modes, variable scope, uniqueness requirements, ordering and duplicate handling, result limits, completeness, and the meanings of no match, ambiguity, contradiction, and unsupported execution. They must not silently reinterpret the declared condition. A single structure, an array of structures, a scalar, or a status packet are different contracts; one result must not silently switch an array into an object.

In the current runtime, a query or constraint declares a problem; solve executes it. Merely mentioning ?xx does not export a value named $xx. An explicit output ?solutions rows creates one output wire whose value is an array of correlated assignments when that projection is supported, including a one-element array when exactly one row is returned. output ?xx one instead requests a unique scalar for that variable, not a whole result structure. For numeric prove/possible problems, the finite backend's rows satisfy require; claim is checked separately rather than filtering those rows. Optimization rows are optimal assignments. The Z3 adapter currently does not support the rows projection. See binding for materialization and reason for execution results.

The knowledge language

Beside the host circuits and the model's strings there is a third group of pages: the knowledge wires that a model or the owner writes from a source (the manual). Choose by the work to be done: declare a relation (predicate), state a claim (fact), a law (rule), a tendency with exceptions (default), a forbidden state (integrity), a total (aggregate), a step and its effects (action), the manual's procedure (method), what may and must be done (norm), a bundle (procedure), a proposed change (amendment, argument), a performed sequence (trace). Their shared meaning is on Knowledge semantics, versions and approval on Governance and modes of work, and the question forms on Query modes.

Executable syntax

There is one SOP grammar with two authoring layers. The small model writes strings and match blocks (How the model writes); trusted circuits written by people, tools and the host use positional atoms of identifiers such as works_at maria acme, exact keyword fields and typed references, and the host lowers every linked model proposition to such an atom. A fact constructs a value, a query describes conditions, solve uses admitted evidence or a session memory view to evaluate them, and remember records explicit facts/events in an authorized session. The individual wire pages list the complete SPEC keyword inventory and field-specific consumer checks. Parser shape, graph dependencies, semantic lowering and permission checks happen at different stages.

A complete question circuit

This trusted circuit uses a local fact explicitly supplied to solve. It does not require admitting that fact into persistent memory. A host schema, when supplied, must declare works_at with argument types compatible with maria and acme.

@statement fact
  holds works_at maria acme
  valid timeless
  source user
  quote "Maria works at Acme."

@question query
  where works_at maria acme
  at 2026-01-01
  asof 2026-01-01
  mode exists

@result solve
  query $question
  data $statement

@answer cnl
  result $result
  language en

The relation has explicit positive support from the supplied fact. The circuit does not claim to have independently verified Maria's employment. The host manages context and execution routing; this full runtime example is not an instruction for the small model to choose every solve field.

Two authoring and evaluation boundaries

The model-authored declarative layer concentrates on reliable NL-to-SOP translation: statements, assumptions and questions, negation and time. Clarification is generated by the host when required identity or scalar input is unresolved or ambiguous. Host-approved metaprograms construct inspectable execution circuits with resolve, pack, remember, solve and cnl as needed. It excludes jsEval and hidden code bodies. Models may propose JavaScript-backed work, reusable reasoning programs, graph algorithms, and collection operations for review. Such extensions require explicit types, effects, permissions, and execution limits; their presence in the system does not enlarge the small model's output grammar automatically.

Formalizer evaluation measures actual predicted SOP against independently reviewed meaning. System evaluation measures memory, reasoning, approved programs, and end-to-end results, distinguishing controlled SOP inputs from model-produced inputs. Executing a gold program alone does not evaluate the model. The reporting contract is in eval/README.md.

Knowledge and authority

User assertions belong to their stated conversational scope. Coding-agent document consolidation retains source quotations, identities, negation, validity intervals, and conflicts before host-approved publication. Source text is data, not permission to install executable definitions. The lexicon wires predicate, lexeme and entity are knowledge wires: the vocabulary of a base memory, from which the KnowledgeLinker links strings to symbols.

The governing language and reasoning contracts are DS004 and DS006. Whitespace atom syntax is the executable grammar. Declarative model outputs and host-expanded execution circuits use this same grammar, while their permissions and responsibilities differ. Training requires separate explicit authorization.
