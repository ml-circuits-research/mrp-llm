All wire types

pattern

A pattern records a candidate regularity for case evaluation. It is not an admitted Horn rule and does not establish that its conclusion follows. Researchers and trusted system/tool circuits may author candidate patterns; admission as a rule requires separate review. Model-authored declarative input cannot.

SOP syntax: @id type, exactly two leading spaces on each field line, $id for a computed value, ~id for a declaration handle, and ?x for a local logic variable or an output name. Atoms use [not ]predicate term1 [term2 [term3 [term4]]] with one to four whitespace-separated terms; lowercase predicate names, canonical symbols, JSON-quoted strings or safe integers. Parenthesized predicate(arg, …) and comma-separated arguments are not executable syntax.

Fields and inputs

KeywordCardinalityAccepted value, default and effect
whenRepeatable; requiredOne predicate atom per line; required one to sixteen conditions. Logic variables in the conclusion must occur in a condition.
thenAt most once; requiredOne conclusion atom in the current whitespace-separated syntax. Its variables must be bound by when.
supportAt most once; optionalNumber from 0 to 1 inclusive, default 0; metadata on the declaration, not a truth probability.
coverageAt most once; optionalNumber from 0 to 1 inclusive, default 0; descriptive metadata, not an automatic validation threshold.
samplesAt most once; optionalFinite nonnegative number, default 0; this parser does not require an integer.
counterexamplesAt most once; optionalFinite nonnegative number, default 0; this parser does not require an integer.
sourceAt most once; optionalPlain/quoted source text, default provided; provenance label only.
statusAt most once; optionalcandidate (default), validated or rejected; does not convert it to a rule.

A ~pattern handle or a $pattern value can enter induce candidates (directly or through a packed $value). A pattern in generic data is ignored for deduction and does not authorize implication.

Result and limits

The declaration produces a typed pattern object with rule-shaped conditions/conclusion and descriptive metrics. induce computes fresh empirical training/holdout metrics and resets evaluated pattern status to candidate; no world write occurs.

rule() accepts 1–16 conditions and enforces range restriction and schema types. Numeric metadata must be finite and within its declared bounds; no logical conclusion is inferred solely from support or the word validated.

Executable examples

Reusable candidate

@signal pattern
  when sensor_alert ?unit
  then inspect ?unit
  support 0.8
  samples 10
  source "pilot cases"

This is a candidate for comparing alert and inspection features in separately supplied traces, not an automatic inspection rule.

Two-condition regularity

@repeat pattern
  when alert ?unit
  when service_due ?unit
  then inspect ?unit
  status candidate
  counterexamples 2

Both conditions must occur in a case before induction scores the proposed conclusion.

Invalid or unsafe use

@bad pattern
  when alert ?unit
  then inspect ?other

The parser accepts the atom shapes, but declaration lowering rejects ?other: a conclusion variable must be bound by a condition.
