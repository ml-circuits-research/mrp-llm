predicate

Declare a relation of the base memory: its arguments with roles and types, its display labels and the copula readings it carries. Its words in a language are lexemes; the classes it types are entities of kind class.

Status and author: Knowledge wire. It lives in the circuits of a base memory (the vocabulary of core-min, core-en or a world) and is written by a person, a model or a mapping tool; the small model never authors it. The lexicon of a base memory is compiled from these wires and its imports (Lexicon.fromCircuits). The retired separate ontology grammar (alias lines, concept) is migrated by tools/convert-ontology.mjs.

Accepted fields

Single means at most once, repeatable means zero or more, and required means at least once. Other field names are rejected (unknown_field). The table is generated from the grammar in sop/knowledge/grammar.mjs.

FieldCardinalityAccepted values and behavior
argsAt most once; required unless role lines are givenrole:type entries in argument order, or none for arity 0 (a state flag). Types: entity integer text time value rational; roles: subject object recipient location source destination instrument time topic, at most one argument per role. At most six arguments. When role lines are also given both spellings must agree (args_disagree_with_roles).
roleRepeatable; one line per argument, in argument orderrole NAME TYPE: NAME is one of the closed role inventory (ROLE_NAMES in sop/enums.mjs); TYPE is a value type or a class symbol (an entity of kind class in this memory or its imports, role_class_unknown otherwise). The class types the argument: a lexeme restrict and the linker use it. Line order fixes the positional atom order.
labelRepeatable; at most one per languagelabel LANG "text": the display form of the relation, which is also a link form with the natural frame (label_duplicate_language for a second one in a language; further forms are lexemes).
domainAt most once; optionalA lowercase symbol that scopes the relation (a topic the memory supplies).
closedAt most once; optionaltrue or false (default false). true says the retained view holds every fact of the relation; declare it only when the source says the list is exhaustive and quote that sentence in description.
keyAt most once; optionalAn argument position (1 to the arity) that determines the rest: a lint (key_violation).
transitiveAt most once; optionaltrue or false, arity 2 only: an advisory routing hint to a closure template.
inverseAt most once; optionalA lowercase symbol: the name of the inverse relation (an advisory hint).
unitAt most once; optionalText: the unit of a numeric argument.
descriptionAt most once; optionalText: what the relation means (and the source sentence for a closed relation).
readingRepeatable, each value at most once; optionalOne of class occupation attribute identity location describe unit_amount unit_dimension: a copula reading the relation carries (bad_enum, repeated_reading, reading_roles_mismatch). It lets the base memory, not the engine, say which predicate answers "Ana is a doctor", "Paris is in France" or "Who is Ana?". The two unit readings are not copula readings: unit_amount marks the predicate that gives how many base units one of a unit is, unit_dimension the one that gives what a unit measures; a comparison of two quantities with units (compare "1 hour" above "3000 seconds") is converted through their facts (sop/quantities.mjs).
describe_rankAt most once; optionalA positive integer: the order among the describe predicates (lowest first); needs reading describe.

What it is for and how to write it

The declaration fixes the arity, the role of each position and its class. The roles are the bridge between the two surfaces: The formalizer writes role subject "Ann" and role object "Alpha Lab", the KnowledgeLinker maps the relation phrase to a predicate through its labels and lexemes, and the roles place each string in its position. A predicate with no label and no lexeme cannot be reached from language (the authoring warning predicate_without_lexeme); an engine test world that refers to predicates by id does not need them.

Examples

Class symbols such as person come from the memory: core-min declares class entity person organization place occupation property unit; the example repeats the classes it uses.

@person entity
  kind class
  label en "person"
@organization entity
  kind class
  label en "organization"
@place entity
  kind class
  label en "place"

@works_at predicate
  args subject:entity object:entity
  role subject person
  role object organization
  label en "works at"
  description "an employment relation"

@lx_works_at_en lexeme
  of works_at
  language en
  pos verb
  form "work at"
  frame subject object

Unit facts for comparisons of quantities

@unit entity
  kind class
  label en "unit"
@dimension entity
  kind class
  label en "dimension"

@base_amount predicate
  args subject:entity object:integer
  role subject unit
  role object integer
  label en "amount in base units"
  reading unit_amount

@dimension_of predicate
  args subject:entity object:entity
  role subject unit
  role object dimension
  label en "dimension of"
  reading unit_dimension

Invalid: a role that names no class and no value type

@works_at predicate
  args subject:entity object:entity
  role subject person
  role object organization

Invalid: a role name outside the closed inventory

@p predicate
  role employee entity

Common mistakes

  1. A role typed with a class the memory does not declare.
  2. Two labels in one language: the second form is a lexeme.
  3. A predicate whose forms all collide with another predicate of the same frame: declare restrict or distinct weights on the lexemes.
  4. Putting the relation phrase of a language into description instead of a label or lexeme.
