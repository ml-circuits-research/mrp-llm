procedure

Stores an approved reusable SOP circuit using the same parameterized runtime expansion contract as template. The name distinguishes library intent; it is not a separate procedure execution engine and neither type grants an imperative function body.

Status and author: Host-approved declaration; a model-origin program cannot install this definition.

Accepted fields

Single means at most once, repeatable means zero or more, and required means at least once at parse time. Other field names are rejected.

FieldCardinalityAccepted values and current behavior
paramsAt most once; optional; default emptyWhitespace-separated distinct parameter names, default empty; names become expansion inputs.
yieldExactly once; requiredWire ID or declared output name produced by the body; determines the value exposed by expansion.
bodyExactly once; required| with four-space-indented SOP source; reviewed definition body expanded by an explicit invocation, not executed upon declaration.
descriptionAt most once; optional; default emptyPlain or JSON-quoted descriptive text, default empty; documentation metadata only.
cueRepeatable; optional; default nonePlain or JSON-quoted cue per line; optional metadata for locating a reviewed definition, not an execution trigger.

Execution and result

Each with name value binds one declared parameter, once. A value beginning with $ resolves an existing wire value; other text is unquoted (a JSON-quoted string is decoded). Missing or duplicate parameters, unknown names, a bad body, ID collisions, or a yield outside body/output are errors. At expansion, the runtime creates namespaced parameter value wires and body wires, substitutes references, renames body output ports, then aliases the expansion result to its yield. Definition metadata does not turn this into arbitrary code execution.

Host-approved ~procedure handles can come from a checksum-verified repository library or a trusted program. A trusted system/tool program can invoke the approved handle using expand, but cannot publish a procedure definition. Nested runtime operations still have their own authorization and cardinality rules. This does not execute arbitrary JavaScript or automatically commit a library.

Current SOP examples

Arithmetic procedure in trusted source

@approved procedure
  description "Compute a validated threshold comparison"
  cue "check threshold"
  params number limit
  yield result
  body |
    @result value
      data $number <= $limit

@actual value
  data 4

@bound value
  data 9

@check expand
  using ~approved
  with number $actual
  with limit $bound

The approved body evaluates a bounded comparison and returns true from 4 ≤ 9; the host is the author of the definition.

Procedure with a status result

@reviewed procedure
  params item
  yield status
  body |
    @q query
      where selected $item
    @s solve
      query $q
      output ?status status

@thing value
  data "sample"

@application expand
  using ~reviewed
  with item $thing

The result is the query status from a generated output port, not a guessed boolean. The query requires an appropriate admitted predicate/knowledge view.

Invalid or unsafe example

@bad procedure
  params x y
  yield result
  body |
    @result value
      data $x + $y

@v value
  data 1

@use expand
  using ~bad
  with x $v

All parameters must be supplied; the expansion rejects the missing y even though the outer fields parse.

Knowledge language: procedure

In the knowledge language a procedure is a named bundle of wires, a mode of work; it has no approval and no version of its own. The tables and examples of this section are about the knowledge form, written from a source and checked by sop/knowledge/; the sections above describe the host-circuit form. Anchors of this section's fields start with kfield-. The language manual is the section "Knowledge wires" of DS004.

Other field names are rejected (unknown_field). The table is generated from sop/knowledge/grammar.mjs.

FieldCardinalityAccepted values and behavior
membersRepeatable; requiredOne or more $id references: the methods, norms, rules and actions that make up the procedure. Required (bad_ref, unknown_ref).
descriptionAt most once; optionalText: what the procedure is for.
scopeAt most once; optionalText: the tasks, agents or contexts it applies to.
sourceAt most once; optionalQuoted citation of the manual.
reportRepeatable; optionalAn atom pattern over declared predicates (variables allowed, no not): the rows the procedure reports. Added 2026-10-03 for analysis procedures (proposal P-8); the arity is checked against the declaration (bad_atom, arity_mismatch).

What it is for

A procedure makes ten wires addressable by one name. The members carry the approval and the versions, so the procedure is in force exactly when its members are, and "which version of the reset procedure applied on that date" is answered from their history (asof). An amendment addresses a procedure by name.

Examples

@a predicate
  args subject:entity
@act action
  params ?x
  requires a ?x
  adds a ?x
@n1 norm
  forbid ~act ?x
@reset_procedure procedure
  members $act $n1
  description "Reset mode of work"
  scope "ops"

Analysis procedures

A procedure whose scope carries the tag analysis is an analysis procedure (DS022 "Analysis procedures", Analysis procedures): the analyzer applies its members, and only its members, to the document layer of a session or a base memory. Its findings are the violations of its integrity members; its report lines are its measures (KPIs, scores). Parameters are member facts of analysis_parameter, which a run may override by name. The library config/knowledge/analysis-core-v1/ holds the starter procedures.

@amount predicate
  args subject:entity object:value
  key 1
  closed true
@upper_limit predicate
  args subject:entity object:value
  closed true
@analysis_parameter predicate
  args subject:entity object:value
  key 1
@kpi_headroom predicate
  args subject:entity object:value
@over_limit integrity
  never all
    amount ?q ?v
    upper_limit ?q ?max
    compare ?v above ?max
  end
  witness ?q
  message "a value is above the maximum the document itself sets"
  severity error
@headroom rule
  when amount ?q ?v
  when upper_limit ?q ?max
  when compute ?h ?max minus ?v
  then kpi_headroom ?q ?h
@p_margin fact
  holds analysis_parameter safety_margin 0
@limits_check procedure
  members $over_limit $headroom $p_margin
  description "Analysis: values against the limits the document sets, and the headroom left"
  scope "analysis, findings, kpis"
  report kpi_headroom ?quantity ?headroom

Invalid: a negated report line

@q predicate
  args subject:entity
@r1 rule
  when q ?x
  then q ?x
@p procedure
  members $r1
  report not q ?x

Invalid: a member that does not exist

@p procedure
  members $missing
