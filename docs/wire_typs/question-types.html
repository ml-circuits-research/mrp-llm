Wire help / Question types

Question types

The corpora (DS015) label every message with one of eighteen question types, and every question word has exactly one formalization (DS014, "Question forms"). The model writes the question it reads and never rewrites it into another form: "all" stays universal, "how long" stays a duration, "why" stays an explanation. This page maps each type to its formalization, the host's answer and one executed example. The message is English (the input edge translates other languages first): content words are English relation lemmas ("work at", "live in") and common nouns, time expressions stay as written ("last year"), names stay as written ("Cătălin"), and the keywords are English. The examples are complete model outputs: they contain only what the message says, as strings, one keyword per line. How to write them is explained in How the model writes; each keyword is documented on query, stated, constraint and unclear.

Types combine with statements: any message may also carry stated propositions (assertions, suppositions, reported speech) and assumed ones (a chosen reading, a presupposition, a closure); see stated or assumed?. A proportional quantifier ("most", "half") has no form yet.

yes_no: Yes/no question

Formalization: where match blocks, no select. Host answer: supported, refuted, both or unknown.

EN “Does Maria work at Acme?”

@q query
  where match
    relation "work at"
    role subject "Maria"
    role object "Acme"
    polarity affirmed
  end

An explicitly negative question ("Does Maria not work at Acme?") asks about the negated proposition and is written with polarity negated; "… or not?" adds nothing and stays affirmed.

wh: Who / what / which

Formalization: the asked role as a ?variable, select it. Host answer: the bindings (entities).

EN “Who works at Acme?”

@q query
  where match
    relation "work at"
    role subject ?who
    role object "Acme"
    polarity affirmed
  end
  select ?who

The variable name is free (?who, ?x); only its position matters.

count: How many (things)

Formalization: mode count, select ?x. Host answer: the number of distinct bindings.

EN “How many people work at Acme?”

@q query
  mode count
  select ?x
  where match
    relation "work at"
    role subject ?x
    role object "Acme"
    polarity affirmed
  end

Counting occurrences in time ("how many times") is a different type: see how_many_times.

universal: All / every / each / no

Formalization: mode every: where is the restriction (who is counted), scope what must hold for each member. Host answer: refuted with counterexamples when a known member fails; supported when every known member satisfies the scope; otherwise unknown.

EN “Is everyone who works at Acme certified?”

@q query
  mode every
  where match
    relation "work at"
    role subject ?m
    role object "Acme"
    polarity affirmed
  end
  scope match
    relation "be certified"
    role subject ?m
    polarity affirmed
  end

EN “Is nobody who works at Acme certified?”

@q query
  mode every
  where match
    relation "work at"
    role subject ?m
    role object "Acme"
    polarity affirmed
  end
  scope match
    relation "be certified"
    role subject ?m
    polarity negated
  end

"No"/"nobody"/"niciun" is the only form with a negated scope; "all" is never rewritten as "nobody … not". The check covers the members known to the host.

when: When

Formalization: role time ?t in the match block, select ?t. Host answer: the validity interval of the matched fact.

EN “When did Ana work at Acme?”

@q query
  select ?t
  where match
    relation "work at"
    role subject "Ana"
    role object "Acme"
    role time ?t
    polarity affirmed
  end

The model never writes a date it was not given; the host binds ?t (host-only span) when the relation has no time argument of its own.

since_when: Since when

Formalization: as when, plus measure start. Host answer: the interval's start (ISO).

EN “Since when has Ana lived in Cluj?”

@q query
  select ?t
  measure start
  where match
    relation "live in"
    role subject "Ana"
    role location "Cluj"
    role time ?t
    polarity affirmed
  end

until_when: Until when

Formalization: as when, plus measure end. Host answer: the interval's end, open when ongoing.

EN “Until when did Ana live in Cluj?”

@q query
  select ?t
  measure end
  where match
    relation "live in"
    role subject "Ana"
    role location "Cluj"
    role time ?t
    polarity affirmed
  end

how_long: How long

Formalization: as when, plus measure duration. Host answer: whole days up to the runtime clock (unbounded without a start).

EN “How long did Ana work at Acme?”

@q query
  select ?t
  measure duration
  where match
    relation "work at"
    role subject "Ana"
    role object "Acme"
    role time ?t
    polarity affirmed
  end

how_many_times: How many times

Formalization: mode count, select ?t, role time ?t. Host answer: the number of distinct validity intervals.

EN “How many times did Ana visit Cluj?”

@q query
  mode count
  select ?t
  where match
    relation "visit"
    role subject "Ana"
    role destination "Cluj"
    role time ?t
    polarity affirmed
  end

where: Where (to, from)

Formalization: role location ?place (destination for "where to", source for "where from"). Host answer: the bindings.

EN “Where does Ana live?”

@q query
  select ?place
  where match
    relation "live in"
    role subject "Ana"
    role location ?place
    polarity affirmed
  end

why: Why / how come

Formalization: mode explain over the proposition (negated for "why not"), no select. Host answer: the status plus explanation: derivation, recorded or none.

EN “Why is Ana ill?”

@q query
  mode explain
  where match
    relation "be ill"
    role subject "Ana"
    polarity affirmed
  end

The question states what is to be explained; the model does not guess the reason. A proposed reason in the message ("Is that because …?") is its own proposition: see the "because" convention in How the model writes.

how: How (means or manner)

Formalization: role instrument ?how. Host answer: the bindings.

EN “How does Ana pay?”

@q query
  select ?how
  where match
    relation "pay"
    role subject "Ana"
    role instrument ?how
    polarity affirmed
  end

"How many" and "how long" are not this type; they have their own forms above.

claim_check: Claim check

Formalization: a yes/no query about the quoted claim; the claim is not stated. Host answer: as a yes/no question.

EN “True or false: Ana works at Acme.”

@q query
  where match
    relation "work at"
    role subject "Ana"
    role object "Acme"
    polarity affirmed
  end

The user asks whether the claim holds; the user does not assert it, so it is not evidence.

multi: Several questions

Formalization: one query per question (@q, @q2, …). Host answer: one answer per query.

EN “Does Ana work at Acme? And does she live in Cluj?”

@q query
  where match
    relation "work at"
    role subject "Ana"
    role object "Acme"
    polarity affirmed
  end

@q2 query
  where match
    relation "live in"
    role subject "Ana"
    role location "Cluj"
    polarity affirmed
  end

"she" has a single possible antecedent, so it is resolved to "Ana" without an assumption. With two candidates the model writes an assumed relation "refer to" or, when neither is preferable, unclear kind ambiguous.

numeric: Numeric problem

Formalization: constraint with var, require/claim and a required task. Host answer: proved, possible or optimal values.

EN “Each table seats 4 to 7 guests. Could one table seat 8?”

@c constraint
  var ?x int 4 7
  claim ?x equal 8
  task possible

Numbers come from the message; constraints need no linking. task is always written, because prove and possible give opposite readings.

none: No question (statements only)

Formalization: one stated per proposition, no query. Host answer: status: context_updated; asserted statements are carried in the conversation.

EN “Ana works at Acme.”

@s1 stated
  relation "work at"
  role subject "Ana"
  role object "Acme"
  polarity affirmed
  certainty asserted

The statement is never written to the knowledge repository.

unclear: Unintelligible or no request

Formalization: unclear kind gibberish or kind no_request, alone. Host answer: a fixed reply asking to rephrase or to ask something.

EN “asdf qwer zxcv”

@u unclear
  kind gibberish

A readable but odd message ("The square circle is red. Is it red?") is not unclear; it is formalized as written.

ambiguous: Ambiguous with no preferable reading

Formalization: unclear kind ambiguous with 2–4 reading lines, alone. Host answer: the readings, numbered, and next: choose_reading.

EN “Did Ana see the man with the telescope?”

@u unclear
  kind ambiguous
  reading "Ana saw the man who had the telescope"
  reading "Ana used the telescope to see the man"

When one reading is preferable, the model does not use unclear: it formalizes that reading and records the choice with assumed basis disambiguation (examples).

Values, comparisons, superlatives, quantifiers, order and follow-ups

These questions keep their corpus types (a value question is wh, a quantified one universal, a before/after one yes_no); the table lists their word forms (compare, rank, except, quantifier, order, fragment).

EN “How old is Ana?”

@q query
  select ?age
  where match
    relation "be old"
    role subject "Ana"
    role object ?age
    polarity affirmed
  end

EN “Is Ana older than Maria?”

@q query
  compare ?a above ?b
  where all
    match
      relation "be aged"
      role subject "Ana"
      role object ?a
      polarity affirmed
    end
    match
      relation "be aged"
      role subject "Maria"
      role object ?b
      polarity affirmed
    end
  end

EN “What is the cheapest project?”

@q query
  select ?p
  rank lowest ?price
  where match
    relation "cost"
    role subject ?p
    role object ?price
    polarity affirmed
  end

EN “Did at least two Delta Project members work at Alpha Lab?”

@q query
  mode every
  quantifier at_least 2
  where match
    relation "member of project"
    role subject ?m
    role object "Delta Project"
    polarity affirmed
  end
  scope match
    relation "works at"
    role subject ?m
    role object "Alpha Lab"
    polarity affirmed
  end

EN “Did Ana join the Delta Project after she started at Alpha Lab?”

@q query
  order ?t1 after ?t2
  where all
    match
      relation "member of project"
      role subject "Ana"
      role object "Delta Project"
      role time ?t1
      polarity affirmed
    end
    match
      relation "works at"
      role subject "Ana"
      role object "Alpha Lab"
      role time ?t2
      polarity affirmed
    end
  end

Without a previous question in the conversation the host answers a fragment with a clarification; with one, it completes the previous question with the roles the fragment gives.

Conditions, chains, temporal clauses and partial understanding

These forms combine with any question type above. A condition or a temporal clause is its own stated wire that the query names with a link line; a question about the answers of another is chained with $q; a part of the message the model cannot write is an unparsed span.

Conditional question: if $s

EN “If Maria works at Alpha Lab, who works at Alpha Lab?”

@s1 stated
  relation "work at"
  role subject "Maria"
  role object "Alpha Lab"
  polarity affirmed
  certainty supposed

@q query
  select ?who
  where match
    relation "work at"
    role subject ?who
    role object "Alpha Lab"
    polarity affirmed
  end
  if $s1

Host answer: the question is answered with the supposition, and only this question uses it (clause_links applied, condition_scoped); the answer is hypothetical and names the condition. "Unless" is unless $s1 with the clause written affirmed.

A question on another question: $q

Host answer: both questions; the second is joined with the first (the host inlines q's conditions with a fresh variable). The first query selects exactly one variable.

A temporal clause: before, after, when, while

EN “Who worked at Alpha Lab before Maria started there on 1 March 2026?”

@s1 stated
  relation "work at"
  role subject "Maria"
  role object "Alpha Lab"
  polarity affirmed
  valid from "1 March 2026"
  certainty asserted

@q query
  select ?who
  where match
    relation "work at"
    role subject ?who
    role object "Alpha Lab"
    polarity affirmed
  end
  before $s1

Host answer: the clause has a readable time, so before $s1 becomes the query period until 1 March 2026 (effect: "until"); after gives from, when/while give during. "Before the audit on 1 March 2026" has the same form: the audit clause is a stated wire with role time "1 March 2026", and the host needs to know its relation. An undated clause leaves the link not_checked, and the question is answered without it. A question that asks about the order of two events uses order instead.

A partially understood question: unparsed

EN “Who worked at Alpha Lab on the day of the big outage?”

@q query
  select ?who
  where match
    relation "work at"
    role subject ?who
    role object "Alpha Lab"
    role time ?t
    polarity affirmed
  end

@u1 unparsed
  span "the day of the big outage"
  near $q
  hint time

Host answer: the host tries to repair each span (a date, a number, a conversation reference, a name, an English synonym); a repaired span fills its variable, and an unresolved one becomes one targeted question ("Which date or period do you mean by "the day of the big outage"?"), reported in unresolved_spans.

Common mistakes the parser rejects

@q query
  mode explain
  select ?who
  where match
    relation "work at"
    role subject ?who
    role object "Acme"
    polarity affirmed
  end

"Why" asks about one proposition; "Who works at Acme, and why?" is two queries.

@q query
  select ?who
  measure duration
  where match
    relation "work at"
    role subject ?who
    role object "Acme"
    polarity affirmed
  end

"How long" measures a time variable written as role time ?t, not an entity.

@q query
  mode every
  where match
    relation "work at"
    role subject ?m
    role object "Acme"
    polarity affirmed
  end

A universal question states what must hold for each member.

Reasoning question forms (not corpus types)

Five further question forms are modes of a query: why_not ("why can't I ...?"), plan ("how do I ...?"), abduce ("what could explain ...?"), conform ("was the procedure followed?") and procedure ("what is the procedure for ...?"). The model writes the question as the mode word with a match block in strings; it never writes via, trace or an identifier, because the host supplies them. A form that no strategy computes is answered not_computable with the formalization shown. They are not among the eighteen corpus labels above. See Query modes.

The circuits for these forms

Every example below is the circuit written for the message; the wire-help test executes it.

EN “Why can't I hard-reset the router?”

@q query
  mode why_not
  where match
    relation "hard-reset"
    role subject "the user"
    role object "the router"
    polarity affirmed
  end

A modal negative "why" asks what blocks the claim; the claim is written affirmed and the modal is the mode. hard-reset stays one word.

EN “What is stopping Ana from joining the project?”

@q query
  mode why_not
  where match
    relation "join"
    role subject "Ana"
    role object "the project"
    polarity affirmed
  end

The blocked clause is the claim.

EN “How do I reset the router?”

@q query
  mode plan
  where match
    relation "reset"
    role subject "the user"
    role object "the router"
    polarity affirmed
  end

The asker is first person ("the user"); the goal is the claim.

EN “What are the steps to reset the router?”

@q query
  mode plan
  where match
    relation "reset"
    role object "the router"
    polarity affirmed
  end

A step or way noun with a to-clause is a plan question; there is no asker.

EN “What could explain the outage?”

@q query
  mode abduce
  where match
    relation "occur"
    role subject "the outage"
    polarity affirmed
  end

A modal "could" or "might" with explain, cause or account for asks for hypotheses; the observation is the claim, and a noun observation is the subject of occur.

EN “What is the procedure for resetting the router?”

@q query
  mode procedure
  where match
    relation "reset"
    role object "the router"
    polarity affirmed
  end

The task is the claim.

EN “Did we follow the reset procedure?”

@q query
  mode conform
  where match
    relation "follow"
    role subject "we"
    role object "the reset procedure"
    polarity affirmed
  end

Following, observing or violating a procedure, or being compliant; the match stays literal and the performed trace is the host's.

EN “Which teams have only certified players?”

@q query
  mode every
  select ?g
  where match
    relation "be a player of"
    role subject ?m
    role object ?g
    polarity affirmed
  end
  scope match
    relation "be certified"
    role subject ?m
    polarity affirmed
  end

A grouped universal: the groups are selected, the members are the restriction, the property is the scope.

EN “Both at once: does Liam grow lavender, and is he the chef at the Bistrița Arena?”

@q query
  where all
    match
      relation "grow"
      role subject "Liam"
      role object "lavender"
      polarity affirmed
    end
    match
      relation "be the chef at"
      role object "the Bistrița Arena"
      role subject "Liam"
      polarity affirmed
    end
  end

"Both at once" or "both … and" makes the yes/no clauses of the sentence one conjunction.

EN “Does the cottage cost more than 30000 lei?”

@q query
  mode exists
  where match
    relation "cost"
    role subject "the cottage"
    role object ?price
    polarity affirmed
  end
  compare ?price above 30000

A measured amount (cost, price, weigh) is a value variable; the unit is consumed.

EN “Did Ana work at Alpha Lab at any point in 2025?”

@q query
  where match
    relation "work at"
    role subject "Ana"
    role object "Alpha Lab"
    polarity affirmed
  end
  overlaps "2025"

"At any point in" asks about some instant of the period (overlaps).

EN “What is the reason that Rafael does not qualify for the bonus?”

@q query
  mode explain
  where match
    relation "qualify for"
    role subject "Rafael"
    role object "the bonus"
    polarity negated
  end

The reason clause is explained; a negated clause stays negated.

EN “Who is a parent of a parent of Ana?”

@q query
  select ?x
  where all
    match
      relation "be a parent of"
      role object ?m
      role subject ?x
      polarity affirmed
    end
    match
      relation "be a parent of"
      role subject ?m
      role object "Ana"
      polarity affirmed
    end
  end

A repeated relational noun chains through a variable.

EN “Is Javier García still playing for Olimpia Sighișoara?”

@a1 assumed
  relation "play for"
  role subject "Javier García"
  role object "Olimpia Sighișoara"
  polarity affirmed
  basis implicature

@q query
  where match
    relation "play for"
    role subject "Javier García"
    role object "Olimpia Sighișoara"
    polarity affirmed
  end

"Still" and "again" presuppose the proposition: an assumed wire with basis implicature.

EN “Who is Ada Lovelace?”

@q query
  select ?x
  where match
    relation "be"
    role object ?x
    role subject "Ada Lovelace"
    polarity affirmed
  end

The copula, identity: the bare relation "be" with the asked object; the host binds it to the description predicate of the lexicon (DS014 "The copula").

EN “Is Paris a city?”

@q query
  where match
    relation "be a"
    role object "city"
    role subject "Paris"
    polarity affirmed
  end

The copula, class membership: "be a" with the class noun as the object; the host reports the lexicon's class and occupation predicates as readings.

EN “Where is Ana?”

@q query
  select ?place
  where match
    relation "be"
    role subject "Ana"
    role location ?place
    polarity affirmed
  end

The copula, location: "be" with a location variable.

EN “Who is the CEO of Acme?”

@q query
  select ?x
  where match
    relation "be the CEO of"
    role object "Acme"
    role subject ?x
    polarity affirmed
  end

The copula, a role relation: an ordinary relation phrase.

EN “Does any employee of Alpha Lab speak German?”

@q query
  mode exists
  where all
    match
      relation "be an employee of"
      role subject ?x
      role object "Alpha Lab"
      polarity affirmed
    end
    match
      relation "speak"
      role subject ?x
      role object "German"
      polarity affirmed
    end
  end

"Any" on a subject noun is an existential variable restricted to the noun's class.
