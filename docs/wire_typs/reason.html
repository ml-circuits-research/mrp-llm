reason

Runs a typed relational or numeric question with explicit inputs and returns a runtime result packet. It is the lower-level reasoning stage used by solve, which also creates link and output wires.

Status and author: Only trusted host/tool circuits may author this operation. Small-model declarative input cannot emit it; host-approved orchestration supplies the required execution steps.

Accepted fields

Single means at most once, repeatable means zero or more, and required means at least once at parse time. Other field names are rejected.

FieldCardinalityAccepted values and current behavior
queryAt most once; exactly one of query or constraint required$query; relational route, exclusive with constraint; evaluates the question against admitted evidence.
constraintAt most once; exactly one of query or constraint required$constraint; numeric route, exclusive with query; evaluates finite arithmetic conditions.
memoryAt most once; optional; query route$link retrieval result; supplies relational evidence, ignored for numeric constraints.
dataAt most once; optional; query route$value or packed local facts/rules; contributes relational evidence, ignored for numeric constraints.
backendAt most once; optional; default autoauto, js, prolog (relational) or z3 (numeric); backend availability/strategy checked at runtime. An explicit non-JS backend without a reasoning field implicitly selects the advanced strategy; write reasoning advanced explicitly. A requested backend is never substituted: an unavailable one, or one requested under reasoning reference, yields unsupported with that backend named.
assumeAt most once; optional; query route$fact (typically source assumption) or a flat pack of facts; marks temporary relational assumptions, ignored on numeric route. Assumed facts stay conditional rather than becoming observed facts.
reasoningAt most once; optional; default host strategyRegistered reasoning strategy name; default host reasoningStrategy (reference by default), except that an explicit non-JS backend makes the default advanced.
modeAt most once; optional; default deducededuce (default) or supported relational reasoning mode; not used on numeric route.
afterRepeatable; optional; default none$wire per line; orders evaluation after its producer, without making that value evidence.

Execution and result

Numeric route supplies declared variables/requirements to a solver. reference requires finite integer domains; advanced chooses Z3 if available, else JS finite fallback. Relational route joins local facts and optional retrieval memory; reference uses bounded JS Horn, advanced chooses Prolog for point queries when installed and JS otherwise. Explicit Prolog cannot handle interval queries. The result packet reports status, completeness, evidence/proof as applicable, ignored inputs and effective route, plus depth: the number of rule applications in the minimal justification of the facts the answer actually used (an observed fact alone is 0, one chained rule is 1). No output keyword is accepted here; use solve for materialized ports.

One qualified side effect is possible: with a repository/session and a nonhypothetical proof, a previously admitted, metadata-verified observed claim used in that proof may be reinforced when both host policy (policy.reinforce is not false) and the memory retention configuration (reinforceOnUse) allow promotion. Mere retrieval or candidate hits never promote anything, hypothetical proofs never promote, and the reason packet reports the promotion count, so the effect is visible rather than hidden. Reasoning does not assert new world facts.

Current SOP examples

Local relational deduction

@evidence fact
  holds parent ana bogdan
  valid timeless

@q query
  where parent ana bogdan
  mode exists

@r reason
  query $q
  data $evidence
  mode deduce

The reason result reflects the local admitted fact; no repository session is required for this route.

Finite numeric possibility

@limits constraint
  var ?x int 1 4
  require ?x > 2
  claim ?x == 3
  task possible

@r reason
  constraint $limits
  backend js

The result reports possibility relative to domain 1–4 and requirement x > 2; no output port is created.

Invalid or unsafe example

@q query
  where parent ana bogdan
  mode exists

@c constraint
  claim 1 == 1
  task prove

@bad reason
  query $q
  constraint $c

Exactly one of query or constraint is required. Runtime/parser shape validation rejects the combined route.
