recall

Retrieves candidate facts relevant to a query from the current memory session; it does not prove the query or assert any retrieved claim.

Status and author: Only trusted host/tool circuits may author this operation. Small-model declarative input cannot emit it; host-approved orchestration supplies the required execution steps.

Accepted fields

Single means at most once, repeatable means zero or more, and required means at least once at parse time. Other field names are rejected.

FieldCardinalityAccepted values and current behavior
queryExactly once; required$query; asks repository retrieval for matching facts, rather than evaluating a proof.
strategyAt most once; optional; default host strategyRegistered retrieval strategy name, default host retrievalStrategy (hybrid by default); determines retrieval route.
afterRepeatable; optional; default none$wire per line; orders retrieval after an earlier value/effect, without altering query.

Execution and result

recall requires both a repository and a session. It calls the linker with no local data, retrieves admitted facts according to the query time and approved stored rules, and returns a kind: retrieval object with facts, selected rules, completeness, probes and a link plan. No data field exists on recall; use link to include local fact/rule data.

exact scans exact visible claims, hybrid tries exact then associative candidates when coverage is partial, auto follows the configured bank, and named engine strategies require matching memory engines. Search budgets or approximate retention may make completeness false. Candidate retrieval is not an inference or global closed-world proof; reason consumes the packet.

Current SOP examples

Session lookup with reasoning

@question query
  where parent ana bogdan
  mode exists

@found recall
  query $question
  strategy hybrid

@judgment reason
  query $question
  memory $found

A repository/session with admitted parent claims is required; the retrieval packet is passed to the reasoner, which decides the query relative to the visible memory view.

Historical exact search

@old query
  where employed ana
  at 2025-04-01T00:00:00Z
  asof 2025-05-01T00:00:00Z
  mode exists

@seen recall
  query $old
  strategy exact

The request asks which eligible facts were known by the as-of time and valid at the requested instant; exact coverage is still relative to the visible session and budgets.

Invalid or unsafe example

@bad recall
  query "parent ana bogdan"

The string is not a query-wire value. The parser accepts field text; runtime rejects it as the wrong input kind.
