remember

remember records specified fact values or revision events in the current repository session. It is a runtime/tool operation with a concrete side effect, not a proof that a statement is true and not automatic publication to a shared library. Model-authored stated and assumed wires are lowered to turn-local facts and never become observed repository facts; an authorized host/tool operation that records an independently admitted fact is distinct: only genuine user assertions selected for admission should be recorded, not quoted material, hypotheses, inferred answers or every fact wire. This explicit operation requires a repository, an active session and host allowWrite. A successful receipt contains status: stored, recorded claim IDs, count and session revision. Repository.commit(session) is a separate host action that advances user history; session recording is already saved and visible in the active session before commit.

Record an admitted catalog statement

@catalog fact
  holds on_shelf book_a shelf_north
  valid timeless
  source "catalog card 17"

@record remember
  input $catalog
  scope session

@catalog constructs the claim value with its provenance; @record asks the runtime to save that claim in the active session. A receipt identifies the stored claim, but does not certify the catalog card. Without @record the fact is only a value. Passing $catalog to solve.data would instead make it temporary evidence for one solution and would not save it.

Query the recorded session

@one fact
  holds on_shelf book_a shelf_north
  valid timeless

@two fact
  holds on_shelf book_c shelf_north
  valid timeless

@batch pack
  items $one $two

@record remember
  input $batch

@question query
  where on_shelf ?book shelf_north
  select ?book
  mode select

@answer solve
  query $question
  after $record
  output ?book many

pack groups the two claim values; one remember operation records both and returns their IDs. after $record places solve after the session write. The query then asks for books on shelf_north; a complete retrieval view that includes those claims can return ["book_a", "book_c"]. The retrieval strategy and any other visible claims determine the actual answer. The host may later commit this session to user history; no SOP field performs that commit or global publication.

Invalid scope

@catalog fact
  holds on_shelf book_a shelf_north
  valid timeless

@bad remember
  input $catalog
  scope library

The field parses, but runtime rejects scope library; session is the only allowed scope. A different failure is attempting this operation without a writable host session.
