rule

Declares a reviewed implication from one or more atom conditions to one atom conclusion. The rule becomes useful only when a trusted program or approved library supplies it to the linker/reasoner; it is not a fact by itself.

Status and author: Host-approved declaration; a model-origin program cannot install this definition. Installation in a session additionally needs reviewed ingestion and allowRules.

Accepted fields

Single means at most once, repeatable means zero or more, and required means at least once at parse time. Other field names are rejected.

FieldCardinalityAccepted values and current behavior
whenRepeatable; required (1–16 at lowering)Atom [not ]predicate term1 ...; each repeated line is a required condition, 1–16 at lowering; shared variables join conditions.
thenAt most once; requiredAtom [not ]predicate term1 ...; conclusion; each head variable must occur in conditions.
validAt most once; optional; default timelesstimeless (default) or ISO/UTC START END interval; bounds rule applicability.
modeAt most once; optional; default logicallogical (default) or causal; causal marking affects counterfactual simulation.
sourceAt most once; optional; default approved-libraryPlain or JSON-quoted provenance text, default approved-library; labels approved rule origin, not proof.

Execution and result

The parser checks atom shapes and mode; lowerRule checks the 1–16 body count, head safety and schema/type consistency. The linker selects rules whose heads match the query and its possible refutation, expands body subgoals and retrieves matching facts; finite Horn reasoning then evaluates relative to admitted evidence. A rule is not automatically stored simply by appearing in SOP. A trusted local program can pass its value through pack.items ~rule then link.data $pack; approved library rules are loaded for memory queries. A model cannot author a new executable implication under origin=model.

Current SOP examples

Trusted local rule and local facts

@parent_rule rule
  when parent ?x ?y
  then ancestor ?x ?y
  mode logical

@fact0 fact
  holds parent ana bogdan
  valid timeless

@inputs pack
  items ~parent_rule $fact0

@ask query
  where ancestor ana bogdan
  mode exists

@linked link
  query $ask
  data $inputs

@result reason
  query $ask
  memory $linked

The trusted host-provided rule supports the ancestor query from the local parent fact. No session write occurs.

Two-condition join

@grandparent_rule rule
  when parent ?grand ?middle
  when parent ?middle ?child
  then grandparent ?grand ?child
  valid timeless

This host-side definition requires both parent edges with the same ?middle; until supplied to a linker with facts it has no answer of its own.

Invalid or unsafe example

@unsafe rule
  when parent ?x bogdan
  then grandparent ?x ?unknown

The parser accepts atom shapes, but lowering rejects an unbound head variable ?unknown. A model-origin declaration is independently forbidden.

Knowledge language: rule

In the knowledge language a rule is a law of the source (no exceptions); its body may use not, absent, compare, compute, order, start_of and end_of, atoms have zero to six terms, and a rule is governed. The tables and examples of this section are about the knowledge form, written from a source and checked by sop/knowledge/; the sections above describe the host-circuit form. Anchors of this section's fields start with kfield-. The language manual is the section "Knowledge wires" of DS004.

Other field names are rejected (unknown_field). The table is generated from sop/knowledge/grammar.mjs.

FieldCardinalityAccepted values and behavior
whenRepeatable; requiredThe body: repeated lines are a conjunction, or one all/any group closed by end. Leaves: an atom, not ATOM (explicit evidence), absent ATOM (closed predicates only, absent_needs_closed), compare A WORD B (above below at_least at_most equal not_equal), compute ?v A WORD B (plus minus times divided_by exact, whole_divided_by modulo power rounded_to rounded_up_to rounded_down_to; integers and decimals, DS004 "Exact arithmetic"), start_of ?t ATOM, end_of ?t ATOM, order ?t1 before|after|same_time ?t2.
thenAt most once; requiredOne atom, possibly negative (then not flies ?x) and possibly with no terms. Every head variable must occur in a positive body atom (unsafe_head).
modeAt most once; optionallogical (default) or causal; causal rules may be used by counterfactual simulation.
validAt most once; optionaltimeless (default) or START END: the period the law applies.
sourceAt most once; optionalQuoted citation of the sentence the rule comes from.
versionAt most once; optionalA positive integer. A revision is a new wire with version N+1 and supersedes $old; the old wire is never edited.
supersedesAt most once; optionalA $id of a wire of the same type with a lower version (supersedes_type_mismatch, version_not_increasing). An approved successor makes its predecessor approval superseded.
approvalAt most once; optionalproposed, approved, contested, rejected, superseded or retired. Written by the host when it accepts the wire; an author never writes it (authoring mode ignores it with governance_ignored). Only approved wires bind, and so do contested ones, flagged.
approved_byAt most once; optionalText. Written by the host at approval; required with approval approved in memory (approval_incomplete).
approved_atAt most once; optionalISO date or timestamp. Written by the host; asof selects the version in force from this date. Required for every norm and every strict method.
retired_atAt most once; optionalISO date or timestamp after which the wire no longer binds.
scopeAt most once; optionalA quoted list of tags (scope "ops, business_hours"). A scoped wire binds when its tags intersect the query context; an unscoped wire always binds.
quoteAt most once; optionalThe exact words of the source, copied byte for byte.

What it is for

Write a rule for "always", "never" and definitions; write a default for "usually". The engine derives positive and negative evidence independently, so two rules with contrary heads give both and nothing unrelated follows. Negation as failure (absent) is allowed only over a closed predicate and may not occur in a cycle (not_stratifiable); compute may not occur in a recursive cycle.

Examples

@parent predicate
  args subject:entity object:entity
@grandparent predicate
  args subject:entity object:entity

@f1 fact
  holds parent ann bob
@f2 fact
  holds parent bob cy

@r_grand rule
  when parent ?x ?y
  when parent ?y ?z
  then grandparent ?x ?z
@q query
  where grandparent ann ?z
  select ?z

Exact arithmetic over a problem's own numbers

A loan of 4000 at a yearly rate of 0.11 for 8 months: the interest in cents, and the number of 1000-sized instalments rounded up. divided_by is exact; rounded_to 0.01 and rounded_up_to 1 round to a multiple.

@loan predicate
  args subject:entity object:value
@rate predicate
  args subject:entity object:value
@interest predicate
  args subject:entity object:value topic:value
@f1 fact
  holds loan kara 4000
@f2 fact
  holds rate kara 0.11
@interest_rule rule
  when loan ?p ?c
  when rate ?p ?r
  when compute ?y ?c times ?r
  when compute ?m ?y times 8
  when compute ?e ?m divided_by 12
  when compute ?i ?e rounded_to 0.01
  when compute ?q ?c divided_by 1000
  when compute ?n ?q rounded_up_to 1
  then interest ?p ?i ?n
@q query
  where interest kara ?i ?n
  select ?i ?n

The smaller or the larger of two values

Three stages in series pass 170, 140 and 100 units an hour: the line passes the smallest, chained with minimum_with. The spare capacity of stage c over stage b cannot be negative: maximum_with 0 is a floor at zero.

@capacity predicate
  args subject:entity object:value
@line predicate
  args subject:entity object:value topic:value
@f1 fact
  holds capacity a 170
@f2 fact
  holds capacity b 140
@f3 fact
  holds capacity c 100
@line_rule rule
  when capacity a ?a
  when capacity b ?b
  when capacity c ?c
  when compute ?m ?a minimum_with ?b
  when compute ?t ?m minimum_with ?c
  when compute ?g ?c minus ?b
  when compute ?s ?g maximum_with 0
  then line c ?t ?s
@q query
  where line c ?t ?s
  select ?t ?s

Invalid: a head variable the body does not bind

@parent predicate
  args subject:entity object:entity
@grandparent predicate
  args subject:entity object:entity
@r rule
  when parent ?x bogdan
  then grandparent ?x ?unknown

Common mistakes

  1. not where absent is meant (the rule never fires); declare the predicate closed true and use absent, only if the source says the list is exhaustive.
  2. A rule written for "usually": a conflict becomes both.
  3. Expecting divided_by to truncate: it is exact; the integer quotient is whole_divided_by.
  4. Negation through recursion (not_stratifiable).
