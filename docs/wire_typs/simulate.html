All wire types

simulate

Simulation compares a checked query against a factual snapshot and a transient state after ground interventions. The what-if route replaces facts; counterfactual mode requires explicitly causal rules. It never writes back to memory. Trusted system/tool circuits can use this operation; model-authored declarative input cannot invoke it directly.

SOP syntax: @id type, exactly two leading spaces on each field line, $id for a computed value, ~id for a declaration handle, and ?x for a local logic variable or an output name. Atoms use [not ]predicate term1 [term2 [term3 [term4]]] with one to four whitespace-separated terms; lowercase predicate names, canonical symbols, JSON-quoted strings or safe integers. Parenthesized predicate(arg, …) and comma-separated arguments are not executable syntax.

Fields and inputs

KeywordCardinalityAccepted value, default and effect
queryAt most once; requiredOne $query query value. Required; its selected variables, filters and time determine both factual and intervened evaluations.
dataAt most once; optionalOne $value, ~declaration or packed $array of admitted facts and approved rules, optionally hypotheses; hypothesis objects in data are not themselves interventions. A numeric constraint cannot be silently discarded.
memoryAt most once; optionalOne $link reference to a retrieval result, normally from link. A query declaration handle is not a retrieval; omitted memory triggers host-backed linking only when a repository/session and a retrieval query are available. Without either, local data is used.
interventionAt most once; requiredOne $fact, $hypothesis, ~hypothesis or packed $array. Facts contribute their atoms, hypotheses contribute all assumptions; all must be ground. A ~fact handle is not accepted by the runtime. Required but an empty pack supplies no changed atoms.
modeAt most once; optionalExact whatif (default) or counterfactual; any other value throws during operation. Counterfactual requires every relevant rule to have mode causal.
reasoningAt most once; optionalA strategy name (plain token), default host policy.reasoningStrategy (reference by default). Built-ins: reference (the js-reference oracle; js-reference and js-oracle are the same route) and the deprecated advanced (the oracle plus optional external backends for deduction and numeric constraints). The host may restrict allowed strategies.
policyAt most once; optionalOne $policy value or ~policy declaration handle. It must lower to a policy object; each specified positive integer budget caps the corresponding host budget by min(host, wire). No policy reference means host limits alone.
outputRepeatable; optionalRepeatable ?name [one|many|rows|count|status] declaration, default one. Each output becomes a deferred $name value if bound; names must be unique and cannot collide with explicit wires. status binds result status even for incomplete results. Other modes require completeness; unusable/unselected modes become blocked, not arbitrary first answers.
afterRepeatable; optionalRepeatable $wire value-dependency reference. Orders execution after that producer; it does not alter inputs, proofs or output. A ~definition handle is graph-checked but is not a value-ordering dependency.

If no explicit memory and a repository/session exist, the runtime links a retrieval view for the query. What-if overlays interventions, removes their explicit opposites and rederives rules. Counterfactual additionally removes observed heads of causal rules and blocks rules from overwriting intervened heads; this is a deterministic causal Horn fragment, not a stochastic causal model.

Result and limits

The result is the relational answer of the query over the intervened world (answers and proof, as for a deduction) with the native fields guarantee, budget, used, hypothetical: true and whatif ({mode, intervention: [atom texts], factual_status, source_memory_modified: false}). Output status binds status; relational one/many/rows/count follow selectOutput and the query selection/count rules, not a plans/explanations projection.

All operations use bounded search (host defaults include maxNodes 5000, maxDepth 8, maxCandidates 512, timeoutMs 3000); a ~policy can only tighten configured limits. The result records completeness and epistemic status relative to supplied finite inputs and the visible memory view, never calibrated truth probability. No operation here writes to the repository; after is only scheduling. An intervention containing both polarities returns inconsistent. Missing facts are unknown, not negative facts. Incomplete retrieval or closure can make outputs unavailable; counterfactual mode with noncausal rules returns not_expressible (reason causal_model_required).

Executable examples

What-if outage

@healthy fact
  holds online server
  valid timeless
@down hypothesis
  holds not online server
@q query
  where not online server
  mode exists
@scenario simulate
  query $q
  data $healthy
  intervention ~down
  mode whatif

The factual query lacks direct support; the hypothetical state replaces online server with its negative counterpart without altering the original fact.

Causal intervention

@base fact
  holds power_on server
  valid timeless
@causal rule
  when power_on ?x
  then running ?x
  mode causal
@off hypothesis
  holds not power_on server
@q query
  where running server
  mode exists
@inputs pack
  items $base $causal
@scenario simulate
  query $q
  data $inputs
  intervention ~off
  mode counterfactual

This trusted/reviewed rule makes the factual running state derivable; intervening on power removes its support in the counterfactual branch.

Invalid or unsafe use

@r rule
  when power_on ?x
  then running ?x
  mode logical
@q query
  where running server
  mode exists
@off hypothesis
  holds not power_on server
@bad simulate
  query $q
  data ~r
  intervention ~off
  mode counterfactual

This parses and runs, but the rule is in logical mode (also the default when mode is omitted); counterfactual simulation returns status not_expressible (reason causal_model_required) because an all-causal rule model is required.
