All wire types

temporal

Temporal reasoning answers a query over validity intervals and known-at history in the selected memory view. It uses Horn deduction constrained by the query time, not event prediction or an independent temporal logic language. Trusted system/tool circuits can use this operation; model-authored declarative input cannot invoke it directly.

SOP syntax: @id type, exactly two leading spaces on each field line, $id for a computed value, ~id for a declaration handle, and ?x for a local logic variable or an output name. Atoms use [not ]predicate term1 [term2 [term3 [term4]]] with one to four whitespace-separated terms; lowercase predicate names, canonical symbols, JSON-quoted strings or safe integers. Parenthesized predicate(arg, …) and comma-separated arguments are not executable syntax.

Fields and inputs

KeywordCardinalityAccepted value, default and effect
queryAt most once; requiredOne $query value, required. Its at instant or during interval and asof known-at cutoff govern the evaluation; omitted query time defaults to runtime now.
dataAt most once; optionalOne $value, ~declaration or packed $array. Facts and approved rules supply evidence; unrelated kinds are ignored/reported, but a numeric constraint cannot be silently dropped.
memoryAt most once; optionalOne $link retrieval result. If omitted with a repository/session, runtime links query-relevant facts; otherwise it uses local data. The retrieval view is bounded and may be incomplete.
reasoningAt most once; optionalA strategy name (plain token), default host policy.reasoningStrategy (reference by default). Built-ins: reference (the js-reference oracle; js-reference and js-oracle are the same route) and the deprecated advanced (the oracle plus optional external backends for deduction and numeric constraints). The host may restrict allowed strategies.
policyAt most once; optionalOne $policy value or ~policy declaration handle. It must lower to a policy object; each specified positive integer budget caps the corresponding host budget by min(host, wire). No policy reference means host limits alone.
outputRepeatable; optionalRepeatable ?name [one|many|rows|count|status] declaration, default one. Each output becomes a deferred $name value if bound; names must be unique and cannot collide with explicit wires. status binds result status even for incomplete results. Other modes require completeness; unusable/unselected modes become blocked, not arbitrary first answers.
afterRepeatable; optionalRepeatable $wire value-dependency reference. Orders execution after that producer; it does not alter inputs, proofs or output. A ~definition handle is graph-checked but is not a value-ordering dependency.

temporal dispatches to the same bounded Horn route used for deduction, with temporal intersections among fact/rule intervals. The reference strategy runs JavaScript. The advanced strategy may choose SWI-Prolog for a supported instant query if available, otherwise reports JavaScript fallback; the chosen backend and fallback are in result.route.

Result and limits

The result contains query answers, count for a count query, proof rows, complete/truncated flags, route and status such as supported, unknown, refuted, both or mixed_temporal. Output status binds status; one/many require a selected ?variable, rows returns bindings, count requires query mode count. Conflicting or incomplete results do not silently materialize a single value.

All operations use bounded search (host defaults include maxNodes 5000, maxDepth 8, maxCandidates 512, timeoutMs 3000); a ~policy can only tighten configured limits. The result records completeness and epistemic status relative to supplied finite inputs and the visible memory view, never calibrated truth probability. No operation here writes to the repository; after is only scheduling. A query at and during cannot coexist. during intersects validity windows; asof bounds what was known in retained memory. Explicit negative evidence differs from missing evidence, and retrieval completeness is relative to the visible view.

Executable examples

Check a past instant

@record fact
  holds open shop
  valid 2026-01-01 2026-02-01
@q query
  where open shop
  at 2026-01-15
  mode exists
@answer temporal
  query $q
  data $record

A local fact valid over January supports the query at January 15; a different instant would not inherit that support.

Intersect a time window

@record fact
  holds open shop
  valid 2026-01-01 2026-02-01
@q query
  where open shop
  during 2026-01-20 2026-02-10
  mode exists
@answer temporal
  query $q
  data $record

The overlapping portion is January 20 through the exclusive February 1 boundary; the entire requested window is not necessarily supported.

Invalid or unsafe use

@q query
  where open shop
  at 2026-01-15
  during 2026-01-01 2026-02-01
  mode exists
@bad temporal
  query $q

The parser rejects a query that sets both at and during; choose one time view.
