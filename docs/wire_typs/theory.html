theory

Records host-approved theory text and a dialect label for a prospective extension compiler. The current built-in reasoning strategies do not compile or execute arbitrary theory bodies.

Status and author: Host-approved declaration; a model-origin program cannot install this definition. Accepting the declaration syntax does not mean the named dialect has a backend.

Accepted fields

Single means at most once, repeatable means zero or more, and required means at least once at parse time. Other field names are rejected.

FieldCardinalityAccepted values and current behavior
dialectAt most once; requiredOpaque dialect label or JSON-quoted name; records the declared foreign-language source. No built-in theory compiler is registered, so supplying this required theory to reasoning reports unsupported_theory.
bodyAt most once; required| followed by four-space-indented backend-language source; retained as reviewed code, not SOP atom syntax.

Execution and result

The lowered object has kind: theory, dialect, body and required: true. A trusted source can declare or package it; model-origin sources cannot declare it. If a theory is included as a required data input to the built-in reasoning registry, the result is unsupported_theory with no silently discarded theory. This differs from rule, whose finite Horn form is implemented. No registered extension compiler for arbitrary dialects is present in the standard route; do not infer executable Prolog/Z3 code from this field. A theory wire by itself produces metadata, not a proof or write.

Current SOP examples

Host-side metadata only

@calculus theory
  dialect "research-prototype"
  body |
    P(a) -> Q(a)

This trusted declaration produces a theory object. The body is retained as text, not executed; no claim about Q(a) follows.

Required theory reports unsupported

@calculus theory
  dialect "research-prototype"
  body |
    P(a) -> Q(a)

@requirements pack
  items ~calculus

@question query
  where q a
  mode exists

@attempt reason
  query $question
  data $requirements

The pack makes the theory a required reasoning input; the built-in strategy reports unsupported_theory. No executable answer is inferred from the opaque text.

Invalid or unsafe example

@invented theory
  dialect "javascript"
  body |
    return process.env.SECRET

A model may not author a theory: the model-origin compiler rejects the declaration with Model authors stated, assumed, unclear, query or constraint; theory belongs to symbolic execution. In a trusted source the parser accepts this opaque text, but the runtime neither executes JavaScript nor grants environment access; a solve that requires it returns unsupported_theory.
