All wire types

trace

A trace is a supplied case with features used for association, induction or analogy. It is case evidence, not automatically an admitted fact. Trusted tool circuits may author open traces; model-authored declarative input cannot; closed true requires reviewed ingestion.

SOP syntax: @id type, exactly two leading spaces on each field line, $id for a computed value, ~id for a declaration handle, and ?x for a local logic variable or an output name. Atoms use [not ]predicate term1 [term2 [term3 [term4]]] with one to four whitespace-separated terms; lowercase predicate names, canonical symbols, JSON-quoted strings or safe integers. Parenthesized predicate(arg, …) and comma-separated arguments are not executable syntax.

Fields and inputs

KeywordCardinalityAccepted value, default and effect
textAt most once; optionalPlain or JSON-quoted descriptive text, default empty. Lexical association tokenizes this value; no fact is derived from its wording.
sourceAt most once; optionalPlain/quoted provenance text, default provided.
closedAt most once; optionalExact true or false, default false. Only reviewed ingestion may set true; induction treats absent conclusions in closed cases as counterexamples.
knownAt most once; optionalOne ISO date or UTC timestamp (or beginning/open sentinel); default null. Stored as knownAt case metadata; association/induction do not filter cases by it.
featureRepeatable; optionalRepeatable ground predicate atom; a trace may have zero features. Explicit negation is an atom with not.

Use ~trace or $trace (or packed arrays) for associate data, induce data/holdout, analogize source/target or associate cue. A $query is also an acceptable association cue; cases in data must be traces.

Result and limits

A typed case object with text, features, closed flag and known-at metadata. Association emits retrieval hints, induction evaluates patterns, analogy maps features; none of these effects asserts the trace features as facts.

Features must be ground after resolving $terms. Closed-world treatment is confined to evaluating supplied closed cases: an open trace missing a feature is unknown. The model-origin guard rejects closed true.

Executable examples

Open maintenance case

@caseA trace
  text "Motor overheated after alert"
  feature alert motor7
  feature overheated motor7
  source "service log"

The case offers two explicit features and wording for lexical comparison; the wording itself is not a third feature.

Explicit contrary evidence

@caseB trace
  feature alert motor8
  feature not overheated motor8
  known 2026-04-12

The negative feature is explicit evidence in this case. Absence of another feature would not have the same meaning.

Invalid or unsafe use

@unreviewed trace
  feature alert motor9
  closed true

Syntactically valid, but Runtime.run(..., {origin: "model"}) rejects it with Model authors stated, assumed, unclear, query or constraint; trace belongs to symbolic execution: a model cannot author any trace, and in particular cannot certify a closed case. A trusted reviewed source is needed.

Knowledge language: trace

In the knowledge language a trace is a performed sequence of ground action steps, the input of mode conform. The tables and examples of this section are about the knowledge form, written from a source and checked by sop/knowledge/; the sections above describe the host-circuit form. Anchors of this section's fields start with kfield-. The language manual is the section "Knowledge wires" of DS004.

Other field names are rejected (unknown_field). The table is generated from sop/knowledge/grammar.mjs.

FieldCardinalityAccepted values and behavior
stepRepeatable; requiredRepeatable, in order: ~action term... with constants only (trace_step_not_ground), optionally ending at DATE. The step is then judged against the versions in force at that date; a step with no at is judged at the query's asof.

What it is for

A trace records what was done. mode conform with trace $t answers compliant or non_compliant with a compliance object: hard violations by id, soft violations with costs, deviations from a strict method and the total cost. A past trace is judged against the versions in force at the time, not today's. Conformance is relational (a trace is a closed, finite record) and lowers to core rules.

Examples

@a predicate
  args subject:entity
@act action
  params ?x
  requires a ?x
  adds a ?x
@n1 norm
  forbid ~act ?x
  when a ?x
  approved_at 2026-01-15
@t trace
  step ~act r7 at 2026-01-20
  step ~act r7
@q query
  mode conform
  trace $t
  asof 2026-02-01
