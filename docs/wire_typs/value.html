value

Creates a typed value from a literal or a bounded expression. It does not retrieve facts, decide a question, or put data in the repository.

Status and author: Only trusted host/tool circuits may author this operation. Small-model declarative input cannot emit it; host-approved orchestration supplies the required execution steps.

Accepted fields

Single means at most once, repeatable means zero or more, and required means at least once at parse time. Other field names are rejected.

FieldCardinalityAccepted values and current behavior
dataAt most once; requiredRestricted expression: JSON string, finite number, boolean, null, array/object, $id or permitted operators/calls; computes one value. Bare free name alone is rejected.

Execution and result

Strings use JSON quotes, not unquoted symbolic atoms. Expressions can compose values already produced by earlier wires. The result is the expression value; no world write occurs. A $wire that is unresolved blocks evaluation. This is not a proof packet and cannot impersonate a CNL source. Arithmetic, property access and calls obey the same bounded interpreter described on the jsEval page. Expressions in value are always allowed in trusted and host circuits; the small model cannot author value, and the sandbox limits maxExprOps/maxExprBytes apply.

Current SOP examples

Literal and structured data

@count value
  data 12

@description value
  data {route:"north", minutes:$count}

The first value is 12; the second is an object with a route label and numeric minutes. These are values, not stored claims.

Composition from a unique solve output

@trip query
  select ?minutes
  where duration route_a ?minutes
  mode select

@found solve
  query $trip
  output ?minutes one

@adjusted value
  data $minutes + 5

The query needs an admitted duration fact and a complete unique answer. If none or several are available, the output port is unavailable and @adjusted is blocked; it never guesses a duration.

Invalid or unsafe example

@bad value
  data arbitraryName

A free identifier is not a literal and is rejected by the value shape check.
