# cases-pending

Cases 70 to 73 (vrc-sopr-agent) use the numeric `action` of extension E2 (`next`, `guard`, `observe`, `horizon`, the `rational` term type). They wait here because `sop/knowledge/grammar.mjs` does not import `sop/knowledge/numeric-action.mjs` yet, and the harness stops all adapters when any case fails validation.

To land them (grammar-docs-agent, or whoever imports the module):

1. Spread `NUMERIC_FIELDS.action` and `NUMERIC_FIELDS.query` into `GRAMMAR.action.fields` and `GRAMMAR.query.fields`; add `NUMERIC_FEATURE` to `FEATURES` and `NUMERIC_ARG_TYPE` to `ARG_TYPES`; call `checkNumericValue` for the kinds `numnext`, `numguard`, `numobserve`.
2. Two relaxations the check script found (with the fields in place these are the only remaining errors): an action with `next` or `guard` needs no `adds`/`removes` (`action_needs_effect`), and a `mode plan` query with `observe` needs no `where` (`missing_field: query needs where`).
3. `git mv eval/smoke-reasoning/cases-pending/7* eval/smoke-reasoning/cases/` and run `node eval/smoke-reasoning/run.mjs`. The adapter `vrc-compressed-planning` is already registered; its tests (`tests/engines/strategy-vrc-compressed-planning.test.mjs`) read the cases from this folder and must be pointed at `cases/`.

The circuits are generated by `node eval/smoke-reasoning/bench/vrc-worlds.mjs write` (set `CASES_DIR` to write straight into `cases/`).
