# Review epistemic objects and reasoning contracts

Read the archived legacy chapters `probably_obsolete/legacy/requirements/23-arhitectura-consolidata.md` through `probably_obsolete/legacy/requirements/29-exemple-integrate.md` (consolidated in the archived registers under `probably_obsolete/specs/legacy-registers/`) and the contract catalog in `sop/contracts/`. Check syntax, denotation and authority separately. A coherent hypothesis is not confirmed, a frequent pattern is not a universal rule, and a plan is not an executed event. Review abduction, negation, temporality, closed-world assumptions and search limits.

For a proposed rule, keep its source and counterexamples. A causal rule needs explicit causal justification; temporal order or co-occurrence is not enough. For an action, check preconditions, effects, bound variables and a non-negative cost. Do not publish rules or policies taken from a conversation without the approval the runtime requires.

Deliver the reviewed SOP file, the reasons for admission or rejection, positive and negative examples and the executable test. Run the regression suites and compare on the shared profiles. Never turn a skipped Prolog/Z3 check into a passed result.
