# Accepted fields in SOP Lang

Generated by `node tools/capabilities.mjs --write` from the parser, declarative boundary and reasoning registry. “Unique” means at most one occurrence; required fields are listed separately. Semantic validation applies in addition to these field constraints. The formalizer authors stated, assumed, unclear, query, constraint, unparsed, pragmatic and instruction (the model language, DS014, DS023). Host-approved metaprograms compile them into inspectable execution circuits without inventing an identity or promoting a hypothesis to a fact.

## `stated`

Unique fields: `relation`, `polarity`, `certainty`, `speaker`.

Repeatable fields: `role`, `valid`, `because`, `so`, `if`, `unless`, `although`, `so_that`, `before`, `after`, `when`, `while`.

Required fields: `relation`, `role`, `polarity`, `certainty`.

Can be authored in model-origin SOP: yes, subject to semantic validation. Model language: a context-free string proposition the user message puts forward, one finite clause per wire (quoted relation phrase and common nouns in the message language, normalized, or in English; closed-inventory roles with names as written; a $id role value names another clause; link lines because, so, if, unless, although, so_that, before, after, when, while name the related clause). The host links it to the lexicon; certainty asserted lowers to a turn-local fact source user used as evidence and carried in caller-owned context; hedged, supposed or reported speech (speaker) is used only conditionally. Never stored or reinforced (DS014).

## `assumed`

Unique fields: `relation`, `polarity`, `basis`.

Repeatable fields: `role`, `valid`, `because`, `so`, `if`, `unless`, `although`, `so_that`, `before`, `after`, `when`, `while`.

Required fields: `relation`, `role`, `polarity`.

Can be authored in model-origin SOP: yes, subject to semantic validation. Model language: a context-free string proposition the model adds. Reported by default (policy modelAssumptions report); branch runs a separate hypothetical solve. basis is descriptive only. Never stored, never carried across turns (DS014).

## `unclear`

Unique fields: `kind`, `language`.

Repeatable fields: `reading`.

Required fields: `kind`.

Can be authored in model-origin SOP: yes, subject to semantic validation. Model language: the only wire of an output (besides pragmatic wires) that is unintelligible (gibberish), has neither a statement nor a question (no_request), or shows an ambiguity the model does not resolve (ambiguous, with 2 to 4 reading lines paraphrasing the candidate readings); the host renders a fixed reply per kind and lists the readings as a clarification (DS014).

## `unparsed`

Unique fields: `span`, `near`, `hint`.

Repeatable fields: none.

Required fields: `span`.

Can be authored in model-origin SOP: yes, subject to semantic validation. Model language: a verbatim span of the message the model could not formalize (span), optionally near the wire it belongs to (near $id) and the slot it probably fills (hint subject, object, time, location, value, relation, reference or other). A role whose value lies in the span holds a placeholder ?variable paired by near and hint. The host repairs spans symbolically (dates, numbers, money, names, the dictionary, the conversation) before linking and asks one question per unresolved span (DS014).

## `pragmatic`

Unique fields: `kind`, `score`, `span`, `near`, `source`, `basis`.

Repeatable fields: none.

Required fields: `kind`, `basis`.

Can be authored in model-origin SOP: yes, subject to semantic validation. Model language: what the message does besides asking or stating (a greeting, thanks, an apology, a closing, a polite word, an emotion), written by the formalizer in the same understanding step with basis llm and an optional verbatim span; alone for a message of courtesy or emotion only. Advisory: the host renders the courtesy reply and the tone of the answer from it; never evidence, never stored (DS023).

## `instruction`

Unique fields: `do`, `kind`, `text`, `span`, `source`.

Repeatable fields: none.

Required fields: `do`.

Can be authored in model-origin SOP: yes, subject to semantic validation. Model language: what the user asks about how the assistant should answer from now on: do set (kind prefix or suffix with the verbatim text, or the style short or detailed), do cancel (one kind, or all) or do list. Never a fact and never evidence: the runtime applies it to the caller-owned behaviour of the conversation, where it becomes a reply wire and a rule of the conversation layer (origin user) that the reasoner follows on every later turn (DS023 Behaviour layer).

## `query`

Unique fields: `mode`, `select`, `scope`, `measure`, `span`, `at`, `during`, `overlaps`, `asof`, `limit`, `rank`, `quantifier`, `order`, `fragment`.

Repeatable fields: `where`, `filter`, `compare`, `except`, `because`, `so`, `if`, `unless`, `although`, `so_that`, `before`, `after`, `when`, `while`.

Required fields: `where`.

Can be authored in model-origin SOP: yes, subject to semantic validation. Model language: match blocks (quoted relation, closed roles, polarity) under where; a $q role value chains the answers of another query (a join); if/unless $s scopes a supposition to this query and a timed before/after/when/while $s bounds its period; mode select, exists, count, explain (why: the answer is a derivation) or every (a universal question: where is the restriction, scope what must hold); role time ?t asks for the validity interval (when), with measure start, end or duration (since when, until when, how long) and mode count for how many times. span is host plumbing (DS014).
